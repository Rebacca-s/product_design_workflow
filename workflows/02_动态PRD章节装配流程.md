# 工作流 02：动态 PRD 章节装配流程

## 概述

本工作流定义了如何在需求类型识别后，动态装配 PRD 章节的完整流程。

PRD 章节不是固定 12 个，而是根据需求类型、复杂度、是否涉及 AI、是否涉及页面、是否涉及状态流转、是否涉及权限、是否涉及数据埋点，动态装配。

## 依赖规则文件

| 规则文件 | 用途 |
|----------|------|
| `rules/需求类型识别规则.md` | 识别需求类型 |
| `rules/交付物启用规则.md` | 决定启用哪些交付物 |
| `rules/PRD章节启用规则.md` | 决定启用哪些 PRD 章节 |
| `rules/PRD章节注册表.md` | 章节库，所有可用章节的登记信息 |
| `rules/PRD章节外拆规则.md` | 判断章节是否外拆 |
| `rules/PRD章节增删规则.md` | 章节的增删改规则 |

## 装配流程

### 阶段 1：需求类型识别

```
用户输入需求
    ↓
根据 rules/需求类型识别规则.md 识别需求类型
    ↓
输出需求类型识别结果（可命中多个类型）
```

### 阶段 2：交付物规划

```
根据 rules/交付物启用规则.md
    ↓
遍历全部交付物（00-07）
  00_交付物与章节规划 → 每次必须
  01_BRD → 新产品/大功能/方向不明时启用
  02_需求分析 → 新产品/大功能启用完整版，小迭代简化
  03_PRD → 每次必须
  04_专项文档 → 有外拆时启用
  05_原型说明 → 涉及页面时启用
  06_HTML原型提示词 → 需要原型时启用
  07_研发检查清单 → 每次必须
    ↓
输出交付物启用规划
```

### 阶段 3：PRD 章节装配

```
根据 rules/PRD章节启用规则.md + rules/PRD章节注册表.md
    ↓
遍历全部章节（A1-A9, B1-B6, C1-C10）
  对每个章节：
    ├── 检查章节分类（通用/条件/AI专属）
    ├── 通用基础 → 默认启用，判断是否简化
    ├── 条件启用 → 检查是否满足启用条件
    └── AI 专属 → 仅 AI 需求时检查启用条件
    ↓
输出章节启用规划（启用/不启用 + 原因）
```

### 阶段 4：生成 PRD

```
根据章节启用规划
    ↓
按顺序生成每个启用章节
  每个章节生成前：
    1. 读取注册表中该章节的"生成前读取"
    2. 读取对应方法论
    3. 读取对应模板
  每个章节生成后：
    1. 根据外拆规则判断是否外拆
    2. 如需外拆 → 生成专项文档 → 主文档保留摘要
```

### 阶段 5：后续交付物

```
根据交付物启用规划
    ↓
按顺序生成：
  05_原型说明文档（如启用）
  06_HTML原型生成提示词（如启用）
  07_研发交付检查清单（动态检查项）
```

## 章节装配决策树

```
需求中包含 AI 关键词？
├── 是 → 启用 C 类 AI 专属章节（按需启用）
└── 否 → 全部 C 类章节不启用

需求是新产品？
├── 是 → A 类全部启用（完整版），B 类按需启用
└── 否 → 继续判断

需求是大功能？
├── 是 → A 类全部启用，B 类按需启用
└── 否 → 继续判断

需求是小迭代？
├── 是 → A 类简化启用，B 类仅命中条件时启用
└── 否 → 继续判断

需求是页面改版？
├── 是 → A6 启用完整版，其他 A 类简化/禁用
└── 否 → 按各章节启用条件逐一判断
```

## 三个典型装配示例

### 示例 1：AI 新产品需求

**需求**："做一个 AI 会议纪要总结小程序"

**需求类型**：新产品 + AI 功能

**启用规划**：

| 分类 | 启用章节 | 不启用章节 |
|------|----------|-----------|
| A 通用 | A1-A9 全部（完整版） | 无 |
| B 条件 | B1(业务流程图)、B2(系统流程图)、B5(埋点) | B3(无状态对象)、B4(单角色)、B6(无特殊风险) |
| C AI | C1-C10 全部 | 无 |

### 示例 2：非 AI 小迭代需求

**需求**："分销记录列表加搜索"

**需求类型**：小迭代 + 非 AI + 后台管理功能

**启用规划**：

| 分类 | 启用章节 | 不启用章节 |
|------|----------|-----------|
| A 通用 | A1(1段)、A2(1目标)、A3(仅列角色)、A4(仅P0)、A5(仅改动)、A6(仅改动页)、A7(仅新字段)、A8(相关异常)、A9(3条) | 无 |
| B 条件 | 无 | B1-B6 全部不启用 |
| C AI | 无 | C1-C10 全部不启用 |

### 示例 3：后台管理功能需求

**需求**："后台新增活动订单状态管理"

**需求类型**：大功能 + 后台管理 + 状态流转

**启用规划**：

| 分类 | 启用章节 | 不启用章节 |
|------|----------|-----------|
| A 通用 | A1-A9 全部（后台模板） | 无 |
| B 条件 | B1(业务流程)、B3(状态流转)、B4(如有权限差异) | B2(简单系统无多系统)、B5(无数据统计)、B6(无特殊风险) |
| C AI | 无 | C1-C10 全部不启用 |

## 与旧版（固定 12 章节）的核心差异

| 对比维度 | v1.0 固定 12 章节 | v2.0 动态装配 |
|----------|-------------------|-------------|
| 章节结构 | 固定 12 章，全部生成 | 25 章章节库，按需装配 |
| AI 章节 | 非 AI 需求写"不适用" | 非 AI 需求不生成 |
| 小迭代 | 同样 12 章结构 | 合并简化，只生成必要章节 |
| 章节变更 | 需修改代码/流程 | 在注册表中登记即可 |
| 新增章节 | 改流程 | 三步登记（模板+方法论+注册表） |
| 交付物 | 固定 6 件 | 动态 4-7 件 |
