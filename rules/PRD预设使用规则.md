# PRD 预设使用规则

## 预设的定位

`templates/presets/` 下的文件是 **PRD 预设方案**，不是强制模板。

- 它们不是最终 PRD
- 它们不是强制章节
- 它们是根据需求类型推荐的章节组合方案
- 最终章节仍然要根据 `00_交付物与章节规划.md` 动态决定

## 预设的作用

PRD 预设只负责提供以下 4 项推荐：

1. **推荐启用哪些章节**：根据这类需求的常见模式，推荐一个章节组合
2. **推荐交付物范围**：推荐启用哪些交付物
3. **推荐写作深度**：推荐各章节的详细程度（完整版/简化版）
4. **推荐专项文档拆分方向**：推荐哪些章节可能需要外拆

PRD 预设不负责强制生成最终章节。

## 6 个预设方案

| 预设文件 | 适用需求类型 |
|----------|-------------|
| `新产品模板_PRD预设.md` | 从 0 到 1 的新产品 |
| `AI功能模板_PRD预设.md` | 涉及 AI 能力的功能需求 |
| `非AI功能模板_PRD预设.md` | 不涉及 AI 的业务功能需求 |
| `小迭代模板_PRD预设.md` | 范围小、改动少的增量优化 |
| `后台管理功能模板_PRD预设.md` | 面向内部运营/管理员的 PC 端后台 |
| `页面改版模板_PRD预设.md` | 不改变功能逻辑的页面调整 |

### 交叉类型说明

以下 3 种需求类型没有独立预设，它们是**修饰类型**，叠加到其他预设上使用：

| 类型 | 作用方式 |
|------|----------|
| 数据统计/埋点需求 | 叠加到任一预设上，启用 B5（埋点设计）章节 |
| 权限/角色需求 | 叠加到任一预设上，启用 B4（权限设计）章节 |
| 状态流转类需求 | 叠加到任一预设上，启用 B3（状态流转）章节 |

例如："后台新增活动订单状态管理" = 后台管理功能模板 + 状态流转类需求（叠加启用 B3）。

## 使用流程

执行 `/product-start` 时：

```
1. 先识别需求类型（10 种类型，可命中多个）
    ↓
2. 根据需求类型匹配一个或多个 PRD 预设
    ↓
3. 从预设中提取推荐章节（作为候选）
    ↓
4. 再根据需求事实特征和用户明确要求进行二次判断
    ↓
5. 按决策优先级（用户要求 > 事实特征 > 类型识别 > 预设 > AI判断）最终确定
    ↓
6. 生成 00_交付物与章节规划.md（含最终章节列表）
    ↓
7. 按 00_规划生成 PRD 主文档和其他交付物
```

## 多预设匹配与冲突处理

一个需求可以同时匹配多个预设：

| 用户输入 | 匹配的预设 |
|----------|-----------|
| "AI 会议纪要功能" | `AI功能模板_PRD预设` + `新产品模板_PRD预设` |
| "后台分销记录新增搜索" | `后台管理功能模板_PRD预设` + `小迭代模板_PRD预设` |
| "AI 客服后台管理" | `AI功能模板_PRD预设` + `后台管理功能模板_PRD预设` + `新产品模板_PRD预设` |
| "首页 Banner 跳转调整" | `小迭代模板_PRD预设` 或 `页面改版模板_PRD预设` |

### 多预设冲突处理规则

当多个预设冲突时，按以下优先级联合决策：

| 优先级 | 规则 | 说明 |
|--------|------|------|
| 1 | 用户明确要求优先 | 用户说启用就启用，不用就不用 |
| 2 | 需求事实特征优先 | 最终决定不在预设，在需求本身 |
| 3 | 更具体的预设优先于更宽泛的预设 | 如 `小迭代` 比 `新产品` 更具体 |
| 4 | 小迭代优先简化 | 小迭代的章节应该简化，不能因新产品预设而展开 |
| 5 | 新产品优先完整 | 新产品的章节应该完整，不能因小迭代预设而过度简化 |
| 6 | AI 预设仅在需求确实涉及 AI 能力时启用 | 非 AI 需求即使命中 AI 预设也不启用 AI 章节 |

### 冲突处理示例

**示例 1**："AI 会议纪要功能" = `AI功能模板` + `新产品模板`

| 冲突项 | 处理 |
|--------|------|
| AI 章节 | 启用（用户明确需要 + 事实特征匹配） |
| 完整度 | 新产品优先完整 → A 类完整版 |
| 最终行为 | 两者不冲突，AI 预设补全 New Product 预设没有的 AI 章节 |

**示例 2**："后台分销记录新增搜索" = `后台管理模板` + `小迭代模板`

| 冲突项 | 处理 |
|--------|------|
| 完整度 | 小迭代优先简化 → A 类简化版 |
| B 类章节 | 后台预设推荐 B3/B4，但小迭代一般不启用 → 检查事实特征后决定 |
| 最终行为 | 以小迭代为主，后台预设提供字段/权限参考 |

**示例 3**："首页 Banner 跳转调整" = `页面改版模板`

| 冲突项 | 处理 |
|--------|------|
| 无冲突 | 仅命中 1 个预设，直接以其推荐为候选 |
| 最终行为 | A6 完整，其他 A 类简化，B/C 不启用 |

## 预设与 00_规划的关系

```
PRD 预设（提供推荐候选）
    ↓
需求事实特征（过滤和修正）
    ↓
用户明确要求（最高优先级覆盖）
    ↓
00_交付物与章节规划.md（最终装配方案）
    ↓
03_PRD_产品需求文档.md（按方案生成）
```

## 预设文件的维护

- 预设文件可以新增、停用、调整
- 新增预设：在 `templates/presets/` 下创建文件 + 在本规则中登记
- 停用预设：在本规则中标注停用，保留文件不删除
- 调整预设：更新文件内容 + 在本规则变更记录中登记
