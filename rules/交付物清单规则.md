# 交付物清单规则

## 核心定位

本项目不是只生成单个 PRD，而是从模糊需求开始，先识别需求类型，再动态决定启用哪些交付物和章节。最终交付给研发的是：**PRD 主文档 + 原型说明 + 必要的专项文档引用路径**。

## 交付物不是固定全量生成

交付物根据需求类型动态启用。每次必须先生成 `00_交付物与章节规划.md`，说明启用/不启用及原因。

详细启用规则见 `rules/交付物启用规则.md`。

## 默认可选交付物

```text
outputs/需求名称/
├── 00_交付物与章节规划.md           ← 每次必须
├── 01_BRD_业务需求说明.md           ← 条件启用
├── 02_需求分析与范围定义.md         ← 条件启用
├── 03_PRD_产品需求文档.md           ← 每次必须
├── 04_PRD_专项文档/                  ← 有外拆时
├── 05_原型说明文档.md               ← 条件启用
├── 06_HTML原型生成提示词.md         ← 条件启用
└── 07_研发交付检查清单.md           ← 每次必须
```

## 各交付物说明

| 编号 | 交付物 | 生成规则 | 说明 |
|------|--------|----------|------|
| 00 | 交付物与章节规划 | **每次必须** | 记录需求类型、启用哪些交付物和章节、原因 |
| 01 | BRD 业务需求说明 | 条件：新产品/大功能/方向不明 | 回答"为什么做" |
| 02 | 需求分析与范围定义 | 条件：新产品/大功能（完整版）；小迭代（简化版） | 定义"做什么、不做什么" |
| 03 | PRD 产品需求文档 | **每次必须**（内容按需装配） | 研发交付的总装文档 |
| 04 | PRD 专项文档 | 条件：有章节满足外拆条件 | 复杂内容的详细展开 |
| 05 | 原型说明文档 | 条件：涉及页面（App/小程序/Web/后台） | 页面清单、跳转、设计说明 |
| 06 | HTML 原型生成提示词 | 条件：需要生成 HTML 原型 | 给 Cursor/Claude 的提示词 |
| 07 | 研发交付检查清单 | **每次必须**（检查项动态生成） | 确认所有交付物完整可用 |

## 交付物之间的关系

```
00_交付物与章节规划（先规划）
    ↓
01_BRD（为什么做）─条件启用
    ↓
02_需求分析（做什么、不做什么）─条件启用
    ↓
03_PRD（怎么做）←── 04_专项文档（复杂细节展开）
    ↓
05_原型说明（长什么样）─条件启用
    ↓
06_HTML原型提示词（让 AI 生成可交互原型）─条件启用
    ↓
07_研发交付检查清单（确认交付物完整）
```

## 核心原则

1. **先规划再生成**：00_规划文档每次必须先生成。
2. **按需启用**：不是每次生成 7 个交付物，根据需求类型动态决定。
3. **每个启用/不启用写原因**：写在 00_规划中。
4. **PRD 是主文档，不是信息堆砌**：复杂内容外拆到专项文档。
5. **所有交付物可独立阅读**：每个文件有完整上下文。
6. **研发拿到的是一套完整的文档包**。

## 需求名称命名规则

- 使用中文简称，便于识别
- 例如：`智能客服对话`、`会员管理后台`、`习惯打卡小程序`
- 不使用日期作为主目录名（日期信息由 git 管理）
