# PRD 章节外拆规则

## 核心原则

PRD 主文档不是所有信息的堆砌，而是研发交付的总装文档。复杂内容必须外拆为专项文档，PRD 主文档通过路径引用专项文档。

---

## 外拆判断条件

某个 PRD 章节满足以下 **任意一条**，就必须外拆成专项文档：

| 序号 | 条件 | 说明 |
|------|------|------|
| 1 | 内容超过 800 字 | 单章文字量过大，影响主文档阅读效率 |
| 2 | 表格超过 2 个 | 表格密集降低主文档可读性 |
| 3 | 涉及成本测算 | 成本测算需要单独评审和审批，独立成文档 |
| 4 | 涉及模型对比 | 模型对比涉及效果/成本/延迟等多维分析，信息量大 |
| 5 | 涉及复杂流程图 | 多分支、多角色、多系统的流程应独立展示 |
| 6 | 涉及多个角色或多个状态流转 | 角色矩阵或状态机图需要完整空间 |
| 7 | 涉及 Prompt 版本管理 | Prompt 版本迭代需要独立追踪 |
| 8 | 涉及评测集设计 | 评测集需要独立维护和版本管理 |
| 9 | 涉及接口、字段、埋点、状态机 | 技术规格类信息研发需要单独查阅 |
| 10 | 研发需要单独实现或单独评审 | 研发侧需要将某内容作为独立工作包 |

> **与注册表的关系**：以上 10 条为通用外拆条件。`rules/PRD章节注册表.md` 中各章节的"外拆条件"字段是**针对该章节的细化约束**（如改为 AND 关系、提高阈值等），细化约束优先于通用条件。判断时先检查注册表中该章节是否有特殊外拆条件，如有则按其执行。

---

## 外拆后 PRD 主文档必须保留的内容

外拆后，PRD 主文档对应章节中 **不能留空**，必须保留以下 4 项：

1. **章节结论**：这一章的核心结论是什么（1-2 句话）
2. **核心规则**：研发必须知道的关键规则（不超过 5 条）
3. **研发必须关注的内容**：哪些内容是研发在实现时必须特别注意的
4. **专项文档路径**：指向 `04_PRD_专项文档/` 中的具体文件

### 主文档保留内容的格式模板

```markdown
## 第 X 章：章节名称

### 核心结论
[1-2 句话总结本章核心结论]

### 核心规则
1. [规则 1]
2. [规则 2]
3. [规则 3]

### 研发关注要点
- [要点 1]
- [要点 2]

### 专项文档
> 详细内容见：[04_PRD_专项文档/XX_章节名称_专项说明.md](../04_PRD_专项文档/XX_章节名称_专项说明.md)
```

---

## 专项文档存放位置

所有专项文档统一放在：

```text
outputs/需求名称/04_PRD_专项文档/
```

## 专项文档命名格式

```text
章节序号_章节名称_专项说明.md
```

### 命名示例

```text
03_模型选型_专项说明.md
04_业务流程图_专项说明.md
05_系统流程图_专项说明.md
08_Prompt工程_专项说明.md
11_验证指标_专项说明.md
12_数据飞轮设计_专项说明.md
```

---

## 外拆执行流程

```
生成章节内容
    ↓
检查是否满足外拆条件（10 条中任意 1 条）
    ↓
┌─ 不满足 → 保留在主文档中，不需要外拆
│
└─ 满足 → 外拆
         ├── 在 04_PRD_专项文档/ 下创建专项文档
         ├── 将详细内容写入专项文档
         └── 在主文档中保留：结论 + 核心规则 + 研发关注要点 + 专项文档路径
```

---

## 外拆好处

1. **PRD 主文档保持在可读长度**：研发不会被数百行的 PRD 淹没
2. **专项内容可独立评审**：Prompt 工程、模型选型、评测集可安排专项评审
3. **专项内容可独立维护**：版本变更时只改专项文档，不动 PRD 主结构
4. **研发可按需深入**：不需要每个研发都通读所有专项文档
5. **主文档保持总装定位**：始终是可通读的完整上下文文档
