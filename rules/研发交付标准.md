# 研发交付标准

## 文档交付标准

研发团队在收到产品经理的交付物后，应能 **不依赖口头沟通**，仅凭文档即可开始开发。

---

## 整体交付标准

| 维度 | 标准 | 说明 |
|------|------|------|
| 完整性 | 按 00_规划启用的交付物全部生成 | 交付物数量不固定，以规划文档为准 |
| 一致性 | 各文档之间无矛盾 | 同一功能在不同文档中描述一致 |
| 可追溯性 | 每个功能可追溯到 BRD 中的业务目标 | 功能不能是凭空出现的 |
| 可读性 | 研发可在 30 分钟内通读 PRD 主文档 | 结构清晰、语言简洁、不过度技术化 |
| 可执行性 | 研发可直接开始编码 | 不需要再找 PM 确认细节 |

## 各文档验收标准

### 01_BRD_业务需求说明.md（如启用）

- [ ] 回答了"为什么做"
- [ ] 明确了业务问题和用户痛点
- [ ] 说明了不做会怎么样
- [ ] 明确了目标用户
- [ ] 明确了业务价值和用户价值
- [ ] 说明了是否需要 AI 及原因
- [ ] 定义了成功标准

### 02_需求分析与范围定义.md（如启用）

- [ ] 定义了用户角色（有画像描述，不是"普通用户"）
- [ ] 定义了核心场景
- [ ] 包含用户故事
- [ ] 明确标注 P0/P1/P2 功能范围
- [ ] 明确写了"不做什么"
- [ ] 列出了依赖条件
- [ ] 列出了风险与假设

### 03_PRD_产品需求文档.md

- [ ] 包含 00_规划中启用的全部章节，无遗漏
- [ ] 未启用的章节不出现在 PRD 中
- [ ] 每个启用章节有实质性内容（不是"待补充"占位）
- [ ] 如果信息不足，明确标注"待确认"和"当前假设"
- [ ] 外拆章节保留了核心结论、核心规则、研发关注要点和专项文档路径
- [ ] 所有专项文档路径可访问
- [ ] 功能规则明确，研发不猜测任何行为

### 04_PRD_专项文档/（如有）

- [ ] 所有外拆的专项文档已生成
- [ ] 每个专项文档命名符合规范（`章节ID_章节名称_专项说明.md`）
- [ ] PRD 主文档中的路径引用正确

### 05_原型说明文档.md（如启用）

- [ ] 页面清单完整
- [ ] 页面跳转关系清晰
- [ ] 每个页面有明确的核心目标
- [ ] 每个页面描述了页面结构
- [ ] 每个页面描述了信息层级
- [ ] 每个页面描述了关键组件
- [ ] 每个页面描述了按钮与操作
- [ ] 每个页面覆盖了：默认态、空状态、加载态、异常态
- [ ] 交互说明清晰（手势、转场、反馈）

### 06_HTML原型生成提示词.md（如启用）

- [ ] 可直接复制给 Cursor / Claude 使用
- [ ] 包含产品背景说明
- [ ] 包含页面范围
- [ ] 包含设计风格要求（配色、字体、质感）
- [ ] 包含交互要求（点击、切换、反馈）
- [ ] 明确输出格式（单 HTML 或按页面拆分）
- [ ] 移动端优先（除非明确是后台系统）

### 07_研发交付检查清单.md

- [ ] 逐项检查了本次启用的所有交付物
- [ ] 逐项检查了本次启用的所有 PRD 章节
- [ ] 标注了未完成项及原因
- [ ] 标注了需要特别关注的风险项

## 研发启动条件

当以下条件全部满足时，研发可以启动：

1. BRD 已获业务方确认（如启用）
2. PRD 主文档中所有启用章节内容完整
3. 00_规划中启用的交付物全部生成
4. P0 需求全部明确（无模糊之处）
5. 原型说明覆盖所有核心页面（如启用）
6. 角色和权限关系明确
7. 异常情况覆盖完整
8. AI 能力边界明确（AI 产品）
9. 验收标准可测试
10. 所有专项文档路径可访问（如有外拆）
11. 研发交付检查清单通过

---

## 不交付给研发的内容

以下内容不需要出现在交付物中：

- 技术架构设计（由研发自行决定）
- 数据库表设计（由研发自行决定）
- 技术选型细节（除非产品侧有强依赖）
- 接口定义（除非有跨团队协作需要）
- 代码层面的实现细节
- PM 的内部讨论记录
- 需求评审中的未采纳方案（除非作为参考附录）

---

## 交付物质量标准

### 信息密度

每个段落、每个表格、每条规则都应该让研发获得新信息。避免：
- "本功能需要仔细设计"（空话）
- "体验要好"（无标准）
- "参考竞品"（不具体）

### 可测试性

所有功能规则必须可被测试：
- 描述具体行为，不用"智能""优化""自动"等模糊词
- 状态流转每个节点都有明确的进入条件和退出条件
- 异常每种情况都有明确的触发条件和处理方式

### 非功能性要求

如果需求涉及以下非功能性要求，必须在 PRD 中明确：

- 性能要求（如：AI 回复在 3 秒内开始流式输出）
- 并发要求（如：支持同时 1000 人在线）
- 兼容性要求（如：iOS 14+、Android 8+）
- 安全要求（如：用户数据加密存储）
- 无障碍要求（如：支持 VoiceOver）
