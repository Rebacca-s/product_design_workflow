# 工具调用透明规则

## 核心原则

每次 Claude Code 与用户对话时，必须透明告知本次使用了哪些插件/Skill/CLI/MCP。这是一个全局规则，适用于所有对话、所有工作流、所有 Skill（包括后续新增的 Skill）。

---

## 一、适用范围

**全局生效。** 适用于：

- 所有 Skill 执行过程（`/product-start`、`/frontend-implement`、后续新增 Skill）
- 所有非 Skill 的普通对话
- 所有 Agent 调用
- 所有 Workflow 调用
- 所有 MCP 调用
- 所有 CLI 命令执行

不因 Skill 不同而有不同行为。

---

## 二、规则目标

每次对话过程中，必须让用户知道：

1. 当前是否调用了插件
2. 当前是否调用了 Skill
3. 当前是否执行了 CLI/命令行
4. 当前是否调用了 MCP
5. 如果没有调用，就明确写"无"
6. 不允许编造，不允许把没有调用过的内容写成已调用
7. 如果无法确定是否调用了某类能力，写"未检测到"，不要猜测

---

## 三、调用前提示规则

当准备调用某类能力时，需要先告知用户正在使用什么。

### 格式

```markdown
## 工具调用提示

Skill：product-start
插件/CLI/MCP：无
```

如果是执行命令行，则写：

```markdown
## 工具调用提示

Skill：frontend-implement
CLI：npm run dev / npm run build / grep / find 等
插件/MCP：无
```

如果调用 MCP，则写：

```markdown
## 工具调用提示

MCP：具体 MCP 名称
插件/Skill/CLI：无
```

如果全部没有调用，则不需要在过程中频繁提示，但结尾必须汇总。

### 多条调用

如果同时调用多个类型的能力，用顿号或列表写清楚：

```markdown
## 工具调用提示

Skill：product-start
CLI：git status、grep
MCP：ide
插件：无
```

---

## 四、对话结尾汇总规则

每次回复结束时，必须追加一个工具调用汇总。

### 格式

如果本次使用了插件/Skill/CLI/MCP：

```markdown
## 本次调用汇总

Skill：product-start
插件/CLI/MCP：无
```

如果调用了多个，用顿号或列表写清楚：

```markdown
## 本次调用汇总

Skill：product-start、frontend-implement
CLI：npm install、npm run build
MCP：ide
插件：无
```

如果全部没有调用，则统一写：

```markdown
## 本次调用汇总

插件/Skill/CLI/MCP：无
```

---

## 五、统计口径

### 插件

指 Claude Code 外部插件、已安装插件、第三方扩展能力。

如果没有明确调用插件，合并到无调用项中，例如：

```text
插件/CLI/MCP：无
```

### Skill

指 `.claude/skills/` 下的 Skill。

例如：

```text
Skill：product-start
Skill：frontend-implement
```

如果没有调用 Skill，合并到无调用项中，例如：

```text
插件/Skill/MCP：无
```

### CLI

指通过终端、命令行、shell 执行的命令。

包括但不限于：

```text
ls
cat
grep
find
npm install
npm run dev
npm run build
pnpm install
pnpm dev
git status
git diff
```

如果没有执行命令，合并到无调用项中，例如：

```text
插件/CLI/MCP：无
```

如果执行了命令，只记录关键命令，不需要记录所有无意义的中间命令。

### MCP

指 Model Context Protocol 相关服务或工具调用。

如果没有调用 MCP，合并到无调用项中，例如：

```text
插件/Skill/MCP：无
```

如果调用了 MCP，要写清楚 MCP 名称。

### 内置工具

指 Claude Code 内置工具（Read、Write、Edit、Glob、Grep、WebSearch、WebFetch、TaskCreate、TaskUpdate、Bash 等）。

内置工具的调用在 `## 工具调用提示` 中不需要逐一列出（否则每条回复都会列出一长串），但通过 CLI 执行的 `Bash` 命令需要在 CLI 项中记录关键命令。

---

## 六、禁止行为

1. 不允许省略结尾汇总。
2. 不允许把没有调用的工具写成调用过。
3. 不允许用"可能""应该"代替事实。
4. 不允许只在部分 Skill 中生效，必须全局生效。
5. 不允许因为本次没有调用工具就省略汇总。
6. 不允许把普通文件读取误写成插件或 MCP，除非确实通过插件或 MCP 读取。
7. 如果只是依据项目内文件、规则、模板进行回答，没有调用插件/Skill/CLI/MCP，结尾写：

```markdown
## 本次调用汇总

插件/Skill/CLI/MCP：无
```

---

## 七、和阶段状态提示规则的结合

如果当前正在执行 `/product-start` 或 `/frontend-implement`，阶段状态卡和工具调用提示都要保留。

| 规则 | 作用 | 不能互相替代 |
|------|------|-------------|
| 阶段状态提示规则 | 说明当前处于什么阶段、下一阶段是什么 | ✅ |
| 工具调用透明规则 | 说明当前调用了什么插件/Skill/CLI/MCP | ✅ |

二者不是同一个东西，不能互相替代。

**同时使用时**：阶段状态卡在前，工具调用提示在后（或在调用能力时即时输出）。

---

## 八、示例

### 示例 1：没有调用任何插件/Skill/CLI/MCP

（在普通对话回答完用户问题后）

```markdown
## 本次调用汇总

插件/Skill/CLI/MCP：无
```

### 示例 2：调用了 Skill 和 CLI

（在执行 /product-start 过程中）

```markdown
## 工具调用提示

Skill：product-start
CLI：无
插件/MCP：无
```

（回复结尾）

```markdown
## 本次调用汇总

Skill：product-start
CLI：无
插件/MCP：无
```

### 示例 3：同时调用 Skill、CLI、MCP

```markdown
## 工具调用提示

Skill：frontend-implement
CLI：grep、git status
MCP：ide
插件：无
```

（回复结尾）

```markdown
## 本次调用汇总

Skill：frontend-implement
CLI：grep、git status
MCP：ide
插件：无
```

### 示例 4：只执行了 CLI 命令

```markdown
## 工具调用提示

CLI：npm run dev
插件/Skill/MCP：无
```

（回复结尾）

```markdown
## 本次调用汇总

CLI：npm run dev
插件/Skill/MCP：无
```

## 九、后续新增 Skill 的兼容要求

以后新增 Skill 时，必须在 SKILL.md 中：

1. 在"依赖规则文件"表格中新增 `rules/工具调用透明规则.md` 的引用
2. 在执行流程中遵守本规则的全部要求
3. 在"核心原则"或"关键行为准则"中增加一条：**每次回复必须按 `rules/工具调用透明规则.md` 输出工具调用提示和结尾汇总**

新增 Skill 的 SKILL.md 模板应包含：

```markdown
## 依赖规则文件

| 规则文件 | 用途 | 读取时机 |
|----------|------|----------|
| `rules/工具调用透明规则.md` | 工具调用透明提示与汇总 | 全流程 |
| ... | ... | ... |
```
