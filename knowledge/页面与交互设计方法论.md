# 页面设计方法论

## 设计原则

### 1. 目标优先

每个页面只服务一个核心目标。如果一个页面要同时完成多个目标，考虑拆分。

**自查问题**：用户离开这个页面时，应该完成什么任务？

### 2. 信息层级清晰

用户进入页面后，应该在 3 秒内理解页面在说什么，知道下一步该做什么。

**方法**：
- 一级信息：用户必须看到的（标题、核心数据、主操作按钮）
- 二级信息：用户可能需要看的（列表内容、辅助信息）
- 三级信息：用户可以主动查看的（详情、说明文字、帮助）

### 3. 状态完整

一个页面至少有 4 种状态要考虑：

- **默认状态**：正常加载完成后的页面
- **空状态**：没有数据/内容时的页面（不要留白，要引导）
- **加载状态**：数据还在加载中的页面（骨架屏 > 转圈 > 白屏）
- **异常状态**：网络错误、服务器错误、权限不足等

**原则**：设计师画的是默认态，产品经理要考虑所有态。

### 4. 操作可预期

用户执行任何操作前，应该能预判会发生什么；操作后，应该能确认是否成功。

**方法**：
- 操作前：按钮文案用动词（"保存录音"而不是"确定"）
- 操作中：按钮态变化（loading、禁用）
- 操作后：明确的反馈（Toast、页面跳转、列表刷新）

### 5. 容错设计

用户一定会犯错误，好设计让错误可以挽回。

**方法**：
- 关键操作前二次确认（删除、支付、发布）
- 可撤销的操作给撤销入口（撤销删除）
- 不可撤销的操作增加操作成本（输入确认文字）

## 移动端设计要点

### 布局

- 重要内容放在屏幕上半部分（拇指热区）
- 底部用 Tab 栏做主导航，顶部做页面内导航
- 关键操作按钮放在底部固定区域，不要随着滚动消失

### 手势

- 点击是最基本的交互，确保可点击区域不小于 44x44pt
- 左滑常用于操作（删除、标记）
- 下拉刷新，上拉加载更多
- 长按用于触发菜单或预览

### 反馈

- 即时反馈：按钮点击有视觉变化（缩放/变色）
- 操作反馈：操作完成后有 Toast/弹窗/动效
- 加载反馈：超过 1 秒的加载要有骨架屏或 loading 动画

### 输入

- 减少输入：能用选择的不要用输入
- 智能输入：键盘类型匹配内容（数字、邮箱、电话）
- 错误提示：实时校验，在提交前就发现错误

## 设计一致性

### 组件复用

同类功能使用相同组件。例如：
- 所有列表项使用统一的卡片样式
- 所有空状态使用统一插画风格
- 所有弹窗使用统一按钮位置（取消在左，确认在右）

### 文案规范

- 按钮文案：动词 + 名词（如"创建项目"）
- 提示文案：发生了什么 + 建议做什么（如"网络连接失败，请检查网络后重试"）
- 空状态文案：当前状态 + 引导操作（如"还没有录音，去录制第一段吧"）

### 视觉层级

- 颜色：主色用于关键按钮和高亮，灰色用于辅助信息
- 字号：标题 > 正文 > 辅助文案
- 间距：相关内容靠近，不相关内容拉远

## 页面设计检查清单

设计每个页面时，逐一检查：

- [ ] 页面核心目标清晰吗？（一句话能说清）
- [ ] 信息层级明确吗？（一级、二级、三级）
- [ ] 默认状态设计了吗？
- [ ] 空状态设计了吗？（有引导操作）
- [ ] 加载状态设计了吗？
- [ ] 异常状态设计了吗？（网络错误、服务器错误、权限不足）
- [ ] 关键操作有反馈吗？
- [ ] 可逆操作有二次确认吗？
- [ ] 手势交互定义了吗？
- [ ] 页面转场关系清楚吗？
