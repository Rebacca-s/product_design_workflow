# PRD 动态装配方法论

## 核心理念

PRD 不是一个固定的模板，而是一个可装配的文档系统。

不同需求类型需要不同的章节组合。好的 PRD 是"刚好够用"——不多不少，每个章节都有存在的理由。

## 装配原则

### 1. 按需启用

每个章节被启用，必须有明确的理由。没有理由 = 不需要。

**反例**：非 AI 功能中生成"Prompt 工程"章节，写"不适用"。
**正例**：非 AI 功能直接不生成 AI 专属章节，PRD 更短更聚焦。

### 2. 最小必要

只生成研发真正需要的章节。额外信息是噪音，会稀释关键信息。

**原则**：如果删掉这一章，研发还能不能正确开发？能 → 不生成。

### 3. 分类装配

| 分类 | 装配策略 |
|------|----------|
| 通用基础（A） | 默认启用，小迭代简化 |
| 条件启用（B） | 满足条件才启用，不满足不生成 |
| AI 专属（C） | 仅 AI 需求时按需启用 |

### 4. 简化而非省略

小迭代需求不是不写 PRD，而是写简化版。

简化 = 保留核心信息 + 去掉已知上下文。

例如：小迭代的"需求背景"，不需要重新解释整个产品定位，1-2 段说明为什么要做这个改动即可。

## 装配决策表

| 需求类型 | A 类通用 | B 类条件 | C 类 AI |
|----------|----------|----------|---------|
| 新产品 + AI | 全部（完整） | 按需启用 | 按需启用 |
| 新产品 + 非 AI | 全部（完整） | 按需启用 | 全部不启用 |
| 大功能 + AI | 全部 | 按需启用 | 按需启用 |
| 大功能 + 非 AI | 全部 | 按需启用 | 全部不启用 |
| 小迭代 | 简化 | 极少启用 | 不启用 |
| 页面改版 | A6 完整，其他简化 | 不启用 | 不启用 |
| 后台管理 | 全部（后台模板） | B3/B4 常启用 | 不启用 |
| 数据统计 | A1-A4 简化，A6 可能启用 | B5 必须启用 | 不启用 |

## 装配检查清单

在生成 PRD 前，确认：

- [ ] 需求类型已正确识别
- [ ] 每个启用的章节都有启用原因
- [ ] 每个不启用的章节都有不启用原因
- [ ] AI 需求没有漏掉必要的 AI 章节
- [ ] 非 AI 需求没有误生成 AI 章节
- [ ] 小迭代需求已标记简化
- [ ] 已选择正确的 PRD 模板
- [ ] 00_交付物与章节规划.md 已生成

## 常见错误

| 错误 | 正确做法 |
|------|----------|
| 非 AI 需求生成 AI 章节并写"不适用" | 直接不生成，不写"不适用" |
| 小迭代生成完整 9 个 A 类章节 | 合并简化，只保留必要内容 |
| 章节启用不写原因 | 每个启用/不启用都要写原因 |
| 所有需求用同一个 PRD 模板 | 按需求类型选择不同模板 |
| 忘记生成 00_规划文档 | 00 是每次必须生成的 |
