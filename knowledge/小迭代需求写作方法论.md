# 小迭代需求写作方法论

## 适用范围

当需求是现有功能的增量优化，范围小、改动少时，使用本方法论。

## 小迭代的识别

满足以下 3 条以上即为小迭代：

- 改动范围在 1-2 个页面内
- 不涉及新流程
- 不涉及新角色
- 不改动数据结构
- 改动点不超过 5 个
- 不需要新权限

## 小迭代 PRD 的简化原则

### 1. 合并而非省略

不是不写，是合并写。

**反例**：小迭代只写一句话"加一个搜索框"。
**正例**：小迭代 PRD 包含必要的上下文和规则，只是每个章节都大幅简化。

### 2. 只写增量

不重复描述已有功能。只写：
- 这次改了什么
- 改动前后的差异
- 新增的规则
- 新增的异常

### 3. A 类章节简化策略

| 章节 | 完整版 | 小迭代简化版 |
|------|--------|------------|
| A1 需求背景 | 完整背景 | 1-2 段，为什么做这个改动 |
| A2 需求目标 | 3-5 个目标 | 1-2 个目标 |
| A3 用户角色 | 完整角色表 | 被影响的角色（1-2 行） |
| A4 功能范围 | P0/P1/P2 | 仅 P0（就是这个小迭代本身） |
| A5 功能说明 | 完整功能说明 | 仅改动点，带 before/after |
| A6 页面与交互 | 完整页面清单 | 仅改动页面 |
| A7 字段与规则 | 完整字段表 | 仅新增/改动字段 |
| A8 异常情况 | 完整异常表 | 仅与改动相关的异常 |
| A9 验收标准 | 5+ 条 | 3-5 条 |

### 4. B 类和 C 类章节

小迭代极少启用 B 类条件章节（除非改动本身涉及状态流转或埋点）。C 类 AI 章节除非迭代的是 AI 功能，否则不启用。

## 小迭代 PRD 模板结构

```markdown
# PRD 产品需求文档 — [需求名称]（小迭代）

## 1. 改动概述
- 改动前：[现状简述]
- 改动后：[预期效果]
- 改动原因：[为什么]

## 2. 改动范围
- 影响页面：[1-2 页]
- 影响角色：[角色]
- 影响功能：[功能]

## 3. 功能说明（仅改动点）

### 改动点 1：[名称]
**改动前**：[描述]
**改动后**：[描述]
**交互规则**：[规则]

## 4. 字段变更（如有）
| 字段 | 变更类型 | 说明 |
|------|----------|------|
| [字段] | 新增/修改 | [说明] |

## 5. 异常情况（仅新增异常）
| 异常 | 处理 |
|------|------|
| [异常] | [处理] |

## 6. 验收标准
- [ ] [标准 1]
- [ ] [标准 2]
- [ ] [标准 3]
```
