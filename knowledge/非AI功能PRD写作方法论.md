# 非 AI 功能 PRD 写作方法论

## 适用范围

当需求不涉及 AI 能力，核心是业务逻辑、CRUD、流程、权限、展示时，使用本方法论。

## 非 AI 功能 PRD 的聚焦点

非 AI 功能的 PRD 应聚焦在：

1. **业务规则**：什么能做、什么不能做、什么条件下做
2. **交互逻辑**：用户操作 → 系统响应
3. **数据规则**：字段、校验、格式
4. **流程**：多步骤操作的前后关系
5. **权限**：谁能看到什么、谁能操作什么
6. **异常**：什么情况会出问题、出了怎么处理

## 非 AI 功能 PRD 章节调整

### 不需要的章节

C 类 AI 专属章节（C1-C10）全部不生成。不需要在 PRD 中写"不适用"占位章节。

### 可能启用的 B 类章节

非 AI 功能也可能启用某些 B 类条件章节：

| 条件章节 | 非 AI 场景下的启用条件 |
|----------|---------------------|
| B1 业务流程图 | 多步骤、多角色操作 |
| B2 系统流程图 | 涉及第三方服务、异步任务 |
| B3 状态流转 | 订单/审核/任务等状态对象 |
| B4 权限设计 | 多角色权限 |
| B5 埋点设计 | 数据统计需求 |
| B6 风险与依赖 | 第三方/资源/排期风险 |

## 非 AI 功能的 PRD 写作重点

### A5. 功能说明

这是非 AI 功能 PRD 的核心章节。必须写清楚：
- 用户操作步骤
- 每步的系统响应
- 交互规则（边界条件、异常处理、权限约束）

### A7. 字段与规则说明

非 AI 功能的字段规则通常更复杂（校验、联动、计算），要写清楚：
- 字段类型和格式
- 必填/选填
- 校验规则
- 默认值
- 字段间联动

### A8. 异常情况

非 AI 功能的异常通常更"确定性"（网络错误、权限不足、数据冲突），穷举即可。

## 非 AI 功能 PRD 质量检查

- [ ] 没有 AI 专属章节（确认没有误生成）
- [ ] 所有业务规则明确（没有模糊描述）
- [ ] 字段校验规则完整（没有遗漏边界）
- [ ] 异常情况穷举完整
- [ ] 验收标准可测试
