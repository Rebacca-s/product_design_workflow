## 二、痛点挖掘

> **写法要求**：必须写明访谈方法 + 访谈人数 + 痛点 3 维评分

### 2.1 用户访谈数据

- 访谈人数：【X 家 / X 人】
- 单次时长：【X 分钟】
- 角色覆盖：【决策者 X 人 + 执行者 X 人 + 反对者 X 人】
- 访谈方法：5 步法（选对人 → 问对问题 → 5 Why 挖根因 → 观察行为 → 量级足够）

### 2.2 痛点 3 维评分

| 痛点 | 频次（1-5） | 强度（1-5） | 支付意愿（1-5） | 总分 | 是否做 |
|-----|-----------|-----------|----------------|------|-------|
| 【痛点 1】 | | | | | |
| 【痛点 2】 | | | | | |
| 【痛点 3】 | | | | | |

> 标准：总分 ≥ 60 才值得做

### 2.3 痛点验证陷阱排查

- [ ] 痛点至少 3 个用户主动提到（不是 PM 引导）
- [ ] 现有方案确认有缺陷（不是"还行"）
- [ ] 决策者和使用者意见一致（或冲突已明确）
- [ ] 用户愿意为解决方案付费

## 三、价值定义

> **写法要求**：必须有公式 + 量化数字，老板只看数字

### 3.1 价值公式

```
价值 = (旧成本 - 新成本) × 频次 × 用户数 - AI 实施成本
```

### 3.2 价值测算

## 五、可行性论证

> **写法要求**：必须过 5 维评分 + 7 红线 + PoC 验证

### 5.1 5 维评分

| 维度 | 评分（0-4） | 评分依据 |
|-----|----------|---------|
| 用户价值 | 【X】 | 【1 句话依据】 |
| 技术可行 | 【X】 | 【1 句话依据】 |
| 成本结构 | 【X】 | 【1 句话依据】 |
| 数据壁垒 | 【X】 | 【1 句话依据】 |
| 商业路径 | 【X】 | 【1 句话依据】 |
| **总分** | **【X/20】** | |

判定：
- 18-20 分 = 立刻立项 ✓
- 14-17 分 = 可立项但补最低维
- 10-13 分 = 高风险，需更多验证
- < 10 分 = 不要碰

### 5.2 7 红线 Checklist

- [ ] 1. 出错代价是否可承担？
- [ ] 2. 用户是否有替代验证手段？
- [ ] 3. 国内合规是否允许？
- [ ] 4. 单位经济模型是否健康？
- [ ] 5. 是否有数据飞轮？
- [ ] 6. 6 个月后能否建立壁垒？
- [ ] 7. 团队是否有 AI 工程能力？

### 5.3 合规论证

| 法规 | 我们的应对 |
|-----|----------|
| 《算法推荐管理规定》 | 【算法备案进展】 |
| 《生成式 AI 管理办法》 | 【用国产模型 / 大模型备案】 |
| 《深度合成管理规定》 | 【生成内容标识方案】 |
| 《网络安全法》 | 【内容安全过滤方案】 |
| 《个人信息保护法》 | 【人脸 / 隐私授权方案】 |

### 5.4 PoC 验证结论

- PoC 周期：【1 周】
- 测试样本：【X 个真实样本】
- 模型选型结论：【主用 X / 备用 Y】
- 效果均分：【X.X / 10 分】
- 成本验证：【单次 ¥X，低于客单价 30%】
- **PoC 判定**：【GO / CONDITIONAL GO / PIVOT / NO GO】

## 六、ROI 测算

> **写法要求**：必须画 J 型曲线 + 敏感性分析

### 6.1 ROI 公式

```
ROI = (年化收益 - 年化成本) / 年化成本
```

### 6.2 年化收益拆解

| 项目 | 数值 | 备注 |
|-----|------|------|
| 客单价 | 【¥X / 年】 | |
| 客户数 | 【X】 | |
| 续费率 | 【X%】 | |
| **年化收益** | **【¥X】** | |

### 6.3 年化成本拆解

| 项目 | 数值 | 备注 |
|-----|------|------|
| 研发成本 | 【¥X / 年】 | |
| 模型 API 成本 | 【¥X / 年】 | 单次成本 × 调用量 |
| 运营成本 | 【¥X / 年】 | |
| 客户成功成本 | 【¥X / 年】 | |
| **年化成本** | **【¥X】** | |
