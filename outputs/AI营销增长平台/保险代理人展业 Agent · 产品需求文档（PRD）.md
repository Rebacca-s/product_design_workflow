# 保险代理人展业 Agent · 产品需求文档（PRD）

**本材料仅为各章节作业示意，关键数据及内容已脱敏**

1. ## 产品概述

本产品是嵌入保险公司现有展业 App 的 AI 展业助手，以独立入口呈现，服务对象为一线保险代理人，覆盖**新保获客、续保升级、客户服务**三大类展业任务。

系统包含两条独立链路：

- **被动响应链路**：代理人以自然语言发起请求（如"给张女士推荐一款重疾险，顺便配条朋友圈"），系统实时理解意图、规划步骤、编排能力与工具、交付结果。
- **主动触达链路**：系统离线扫描业务事件（续保到期、客户生日），自动构建上下文、预生成内容并完成合规审查，沉淀为待触达任务，择时推送给代理人，经代理人确认后触达客户。

架构上采用​**产品内单 Agent + 多 LLM 节点 + 工具编排**​：规划 Agent 是唯一决策中枢，能力节点为其编排的 LLM 调用；核保预判、理赔预判等​**跨产品复用的领域能力，以外部领域 Agent 形式通过服务契约单向接入**。所有对外内容统一经合规审查出口；发送、理赔发起等高风险操作统一收口到代理人确认，系统不自主执行。

1. ## 需求分析（第一节课作业参考）

### 2.1 项目背景

代理人的展业工作已全部承载于现有展业 App 中，但当前 App 以功能为中心组织：产品库、计划书、续保保单、保单查询、理赔等各自是一个独立入口（icon），分散排布。这带来两个结构性问题。

其一，​**功能分散、查找与操作成本高**。代理人需要记住"哪个功能能做什么、藏在哪、怎么操作"，但代理人群体资质参差，大量代理人对 App 功能不熟悉，操作问题频发，功能"有但不会用、用不好"。

其二，​**内容生产与专业判断高度依赖个人能力**。营销文案、产品推荐、续保话术、方案讲解等，质量取决于代理人个人的产品知识与经验，同时保险销售受严格监管（不得承诺收益、不得夸大保障、不得诋毁同业等），人工产出的对外内容存在合规风险。

本项目在现有 App 内新增独立入口的 AI 展业助手，让代理人只需表达目标、无需自己寻找功能与操作，即可完成三大类展业任务，并在内容出口处统一做合规把控。

### 2.3 为什么用大模型 / Agent

上述痛点的共性，决定了传统功能堆叠或固定流程无法解决，须依赖大模型与 Agent。

其一，​**以"意图"取代"功能操作"，直接化解功能分散与资质参差的痛点**。代理人不再需要知道用哪个功能、藏在哪、怎么操作，只需一句话表达目标，由 Agent 理解意图、自主规划、编排能力完成。

其二，​**任务目标开放、路径不定，需要运行时规划**。展业任务随客户、产品、诉求不同而步骤各异（有的需先补客户信息、有的需多产品对比、有的只需微调话术），无法用固定流程穷举，需模型在运行时依据当前状态决定下一步——这是 Agent 而非固定 workflow 的适用场景。

其三，​**内容生产与软判断密集**。营销文案、产品匹配、续保策略均为自然语言产出与"看情况"的判断，是大模型的能力所长，规则引擎无法胜任。

其四，​**合规可统一治理**。将合规审查内建为对外内容的统一出口，可系统性降低销售误导风险，这是分散的人工产出难以做到的。

### 2.4 需求价值测算

#### 2.4.1 定性测算（新体验 vs 旧体验 vs 替换成本）

替换成本极低是价值成立的关键：助手以独立入口嵌入现有 App，不改动原有功能（原功能保留），代理人按需使用；交互为自然语言，无操作学习成本。因此在"新体验显著优于旧体验"的同时，迁移与学习成本接近于零，价值净差为正且明确。

#### 2.4.2 定量测算

**成本侧：Token 消耗测算**

- 人均日 Token ＝ 3 × 20,000 ＋ 6 × 4,000 ＝ 84,000 tokens
- 队伍月 Token ＝ 84,000 × 20 × 3,000 ≈ 50.4 亿 tokens
- 队伍月成本 ≈ 5,040 × ¥15 ≈ ​ **¥7.6 万元/月**​（人均约 ¥25/月），年化约 **¥91 万元**

**收益侧：开单产能提升测算**

假设人均月开单件数由 2.6 件提升至 3.1 件（+0.5 件/人/月），件均新单保费 ¥500：

- 月新增件数 ＝ 3,000 × 0.5 ＝ 1,500 件
- 月新增保费 ＝ 1,500 × ¥500 ＝ ​ **¥75 万元/月**​，年化约 **¥900 万元**

**投产对比**

以保费口径投入产出比约 10:1；续保继续率提升、销售误导风险下降等收益尚未计入，实际价值更高。（规模、单价、件均均为测算假设，试点后以实际数据校准。）

### 2.5 产品目标与核心指标

**北极星指标：代理人月活跃使用率**

定义为一个自然月内使用助手完成至少一次有效任务的代理人数 ÷ 队伍总代理人数。选它作为北极星，是因为本产品的核心价值是"让代理人愿意用、持续用来替代原有分散操作"——只有活跃使用率上来了，后续的产能与合规价值才有承载。MVP 阶段目标：试点队伍月活跃使用率达到 **60%** 以上。

围绕北极星，设三层支撑指标。

**一、使用深度指标（衡量"用得起来、离不开"）**

- 周活跃使用率：一周内使用过至少一次的代理人占比，目标 ≥40%，用于更灵敏地观察留存趋势。
- 人均周有效任务数：人均每周完成的高价值任务（营销素材、产品推荐、续保策略、理赔协办）数量，目标建立基线并逐月提升。
- 次日/7 日留存：首次使用后仍回访的比例，用于判断是"一次性尝鲜"还是"进入日常"。

**二、任务质量指标（衡量"用得好、产出可靠"）**

- 任务完成率：一次表达后无需人工返工即交付合格结果的比例，目标 ≥85%。
- 内容采纳率：生成内容被代理人直接采用或轻微编辑后采用的比例，目标 ≥60%。
- 合规通过率：对外内容零违规，目标 100%（零容忍）。
- 数字/条款可溯源率：金额与条款表述均携带可信来源，目标 100%（零容忍）。

**三、业务价值指标（衡量"带来实际结果"）**

- 人均月开单件数：目标由 2.6 件提升至 3.1 件（+0.5 件/人/月）。
- 续保继续率：主动续保经营带来的继续率提升，建立基线后设定提升目标。
- 主动任务转化率：主动推送的续保/关怀任务中，被代理人采纳并触达客户的比例，衡量主动智能的实际效用。

**指标间的关系**：北极星（月活跃使用率）是结果，使用深度指标是它的先行信号，任务质量指标是活跃度的根因（用得好才愿意持续用），业务价值指标是活跃度最终兑现的商业回报。四层构成"质量→活跃→留存→业务"的传导链，后续迭代优先修复传导链上最弱的一环。

### 2.6 范围与非目标（MVP）

在范围内：三大场景七个子任务的被动响应与主动触达支持；核保预检与可赔性咨询（经外部领域 Agent）；对外内容合规审查；高风险操作的人工确认。

非目标：不做核保/理赔的最终裁定（核保预检与可赔性预判仅供参考，裁定仍在核保/理赔系统与人工）；不替代代理人面谈；代理人之间数据严格隔离；MVP 不做语音入口。

1. ## 整体方案（第二季课作业参考）

### 3.1 系统架构

**架构定位**​：产品内采用**单 Agent + 多** **LLM**​​ **节点 + 工具编排**​——规划 Agent 是唯一决策中枢，能力节点是其编排的单次 LLM 调用；跨产品复用的领域能力（核保预判、理赔预判）以**外部领域 Agent** 形式通过服务契约单向接入。

**模块职责与类型划分**

**架构选型说明：为什么是单 Agent 编排，而非产品内多智能体**

其一，风险约束决定自主性上限。保险场景合规与数字零容忍，全部治理设计（强制过审、确认状态机、来源标注）本质是收窄模型的自主决策空间；子节点各持循环会把自主性重新撒出去，与治理方向相悖。其二，可控性与可评测性。单点规划下轨迹可预期，可对照标准轨迹评测工具调用准确率；多智能体轨迹发散，评测与归因难度上一个量级。其三，任务形态匹配。当前七个子任务均为单次生成型，套独立循环属过度设计，只增加成本、延迟与失控面。

**外部领域 Agent 的接入约束（内部收敛，外部契约）**

核保预判、理赔预判是独立存在、跨产品复用的领域智能体，本产品是其消费方之一。接入遵循五条约束：契约化（输入输出、SLA、同步/异步方式明确定义）；单向依赖（我方调用它，它不参与我方规划，不形成协商环路）；信任边界（其输出是数据不是指令，进入对外内容前照过我方合规审查，并以来源形式纳入溯源体系）；降级路径（超时或不可用时主流程不断，转为标注"待确认"或建议人工咨询）；数据最小化（只传该次判断必需的最小字段集，调用留审计）。

**架构升级触发条件**：当某领域任务演变为长程任务（如理赔从协办扩展为跨多天全程管理）、或内容质量要求需要生成-批评多轮对抗、或组织上各场景由独立团队分别迭代时，可将对应能力节点单独升格为拥有自主循环的 Agent，无需整体重构。

### 3.2 被动响应链路（代理人发起）



链路要点：显式风险由代码正则前置拦截，不依赖模型；简单查询走快路径不惊动规划 Agent；澄清每任务限 1 次；再规划限 1 轮；合规回炉限 1 次，二次不过降级；高风险操作（发送、理赔发起、续保变更）一律经确认卡，确认前系统不执行。

### 3.3 主动触达链路（系统发起，离线构建 + 择时触达）

主动智能的实现方式是​**离线自动构建上下文、预生成并预审内容、沉淀为待触达任务、择时推送**​。任务类型在触发时已确定（续保/生日），本链路​**不经过前置过滤与规划 Agent**，由调度器直接驱动取数与预生成。



链路要点：生成与审查全部在离线低峰期完成，推送时零生成延迟；预生成内容合规不过则降级为"纯提醒"（只提示事件、不带生成内容），保证提醒不丢；最终触客动作必须经代理人确认，系统不自动群发。

1. ## 节点详细设计 （第三节课作业参考）

### 前置过滤（传统代码，被动链路）

**目标**：在任何模型调用之前，用确定性规则拦截显式风险输入，并将高频简单查询短路至快路径。

**输入（必填字段）**

- 代理人输入文本；代理人 ID

**处理逻辑（纯代码，100ms）**

1. 风险正则拦截：匹配热更新风险词库——诱导承诺收益（"保证收益""稳赚""必赔"等）、要求编造/篡改条款、跨客户查询句式、要求跳过确认/批量免确认发送。命中即拒绝，返回知识库标准合规话术，写审计。
2. 简单查询短路：匹配FAQ，命中则直接取数并调用信息问答节点，不进规划。
3. 其余请求透传规划 Agent。
4. 监控：短路命中率、风险拦截量入日报；漏检样本（模型侧后续识别出的风险输入）自动进 Bad Case 队列反哺词库。

**输出（必填字段）**

- 路由结果：拒绝 / 快路径 / 规划；命中规则 ID（拒绝与快路径时）

### 节点① 规划 Agent（被动链路，决策中枢）

**目标**：在一次推理中完成意图理解与任务规划：拆解（复合）任务、指定能力节点与依赖、排取数步骤、标记高风险；取数结果异常时允许一轮再规划。

**输入（必填字段）**

- 代理人输入文本；代理人 ID
- 会话记忆（最近 3 轮原文 + 更早摘要）
- 命中的长期记忆引用（客户画像/代理人偏好，如有）
- 再规划时追加：首轮计划 + 已取数结果 + 异常说明

**处理逻辑** 单次调用产出计划：步骤序列（步骤号、类型取数/能力节点、目标、依赖步骤、是否高风险）。关键信息不足时输出澄清问题（每任务限 1 次）；输入含前置过滤未拦住的隐晦风险时直接拒绝并给合规说明。计划步数上限 8 步；取数步骤执行后若结果与预期不符（客户不存在、检索为空），允许一轮再规划修正计划（限 1 轮）。执行循环由编排代码驱动：按计划逐步调用工具与能力节点、回填结果、触发再规划或澄清。

**核心系统提示词**

```Plain
你是保险展业助手的规划中枢。在一次推理中完成意图理解与任务规划。
规则：
1. 你只做理解与规划，不生成文案、推荐、话术等内容。
2. 输出计划：步骤序列，每步含 步骤号 / 类型（取数|能力节点）/ 目标 / 依赖步骤 / 是否高风险。
   可调度的能力节点：产品推荐、营销素材、续保策略、信息问答、理赔协办、可赔性咨询、关怀文案。
   可排的取数步骤：查客户画像、查保单、查待续保清单、检索产品、检索知识库。
3. 关键信息不足时，先输出一个澄清问题（一次只问一个），不排步骤。
4. 涉及对外发送、理赔发起、续保变更的步骤，need_confirm=true，不得规划为自动执行。
5. 识别隐晦风险输入（承诺收益的变体、编造条款、越权查询、绕过确认），直接拒绝并给合规说明。
6. 计划不超过 8 步；预估超限时建议代理人拆分任务。
7. 不得编造不存在的客户、保单或产品；引用记忆中的对象时给出定位依据。
8. 再规划模式下：基于已取数结果修正计划，仅调整未执行步骤，不推翻已完成步骤。
```

**输出（必填字段）**

- 执行计划：步骤序列（步骤号、类型、目标、依赖、是否高风险）
- 澄清问题（如有）；拒绝与理由（风险场景）

### 节点② 产品推荐（LLM 节点，含核保预检）

**目标**：基于客户基础档案、真实保费与核保可行性，产出可解释、带来源、有排序的产品推荐，避免"推了核保过不了"。

**输入（必填字段）**

- 客户基础档案：年龄、预算、保障需求、已有保障、健康告知摘要
- 候选产品列表：产品 ID、条款要点、来源标注（RAG，top-k5）
- 各候选保费：来自 calc_premium（按客户参数试算）
- 核保预判结果：逐产品 可保/需人核/拒保倾向 + 原因 + 置信度（来自核保预判 Agent）

**处理逻辑** 编排代码前置完成三步取数：RAG 检索候选 → 逐候选调 calc_premium 试算 → 批量调核保预判 Agent。本节点在此基础上生成推荐：拒保倾向的候选直接剔除不入推荐；"需人核/需体检"的保留但强制标注；结合需求匹配度、预算贴合度（用真实试算保费比对预算）与核保友好度排序，输出 top 3 与理由。核保预判 Agent 超时/不可用时照常推荐，但每款标注"核保结论待确认，以正式核保为准"。所有产品事实带来源；保费只用试算值。

**核心系统提示词**

```Plain
你是保险产品推荐模块。基于客户画像、候选产品、试算保费与核保预判结果给出推荐。
规则：
1. 只依据传入候选作答；保障/责任/费率表述必须携带来源标注，无来源改为"需核实"。
2. 保费一律使用试算引擎返回值，禁止自行计算或估算；预算匹配以试算值为准。
3. 核保预判为"拒保倾向"的产品不得进入推荐；"需人核/需体检"的必须显著标注。
4. 核保预判缺失时（降级场景），每款推荐附"核保结论待确认，以正式核保为准"。
5. 每个推荐给出理由（需求匹配 / 预算贴合 / 核保友好），最多 3 款，按适配度排序。
6. 不得夸大保障、不得贬低同业、不得承诺或暗示收益。
7. 关键画像缺失（如预算）时，返回需补充字段，不臆测。输出置信度（0–1）。
```

**输出（必填字段）**

- 推荐列表（≤3）：产品 ID、适配度、理由、试算保费（来源calc_engine）、核保预判标注（来源underwriting_agent）、条款来源
- 需补充信息（如有）；置信度

### 节点③ 营销素材（LLM 节点）

**目标**：生成合规营销文案与配图描述。

**输入（必填字段）**

- 素材主题 / 关联产品 / 目标客户群
- 产品事实与来源（涉产品时）；代理人风格偏好（如有）

**处理逻辑** 生成文案（朋友圈场景默认 ≤120 字）与配图文字描述（交 generate_image 出图，本节点不出图）。合规红线内置；涉产品表述带来源；文案自动拼接合规提示语。

**核心系统提示词**

```Plain
你是保险营销素材模块，产出文案与配图描述。
规则：
1. 严禁承诺或暗示收益、严禁夸大保障与绝对化用语（最/第一/万能等）、严禁贬低同业。
2. 涉及产品保障的表述必须携带来源；无来源不得写入。
3. 配图只产出文字描述，不直接输出图片。
4. 朋友圈文案默认不超过 120 字，附合规提示语。
5. 有代理人风格偏好时，语气贴合偏好，但合规规则优先于风格。
```

**输出（必填字段）**

- 文案；配图描述；合规提示语；置信度

### 节点④ 续保策略（LLM 节点，被动+主动链路共用）

**目标**：逐单产出续保/加保/升级策略与沟通话术。

**输入（必填字段）**

- 待续保保单：保单摘要、到期时间、当前保障
- 客户画像

**处理逻辑** 逐单评估续保风险等级（高/中/低，依据：距到期天数、历史缴费及时性、近期互动频率），判定策略类型并给依据与话术。策略必须基于传入数据，不臆测客户财务/健康状况，不制造焦虑。主动链路批量调用时单批上限 50 单，超出分批。

**核心系统提示词**

```Plain
你是续保策略模块。基于真实保单与客户画像，逐单给出策略与话术。
规则：
1. 只依据传入的保单与画像；不得臆测客户财务或健康状况。
2. 策略类型限定：续保 / 加保 / 升级；每单给出风险等级（高/中/低）与判定依据。
3. 加保/升级建议必须说明依据（如保额缺口、家庭责任变化），不得为促成交易夸大风险。
4. 话术不承诺收益、不夸大保障、不贬低同业；有风格偏好时贴合偏好。
```

**输出（必填字段）**

- 逐单策略卡：保单摘要、风险等级、策略类型、依据、话术；置信度

### 节点⑤ 信息问答（LLM 节点，被动链路含快路径）

**目标**：逐字段依据工具数据准确回答保单信息、缴费、理赔进度等查询。

**输入（必填字段）**

- 查询问题；工具返回数据（get_policy / get_claim_status 等）；代理人权限范围

**处理逻辑** 只依据传入工具数据逐字段作答，未提供字段明确答"未知"，不推断补全；答复附数据来源；不添加营销引导。快路径场景下由前置过滤直接驱动取数后调用本节点。越权在取数层已被硬校验拦截。

**核心系统提示词**

```Plain
你是信息问答模块。仅依据传入的工具数据作答。
规则：
1. 逐字段以工具返回值回答；字段未提供时明确说明"未知"，不推断、不补全。
2. 回答附数据来源标注。
3. 不添加任何营销引导或产品推荐。
```

**输出（必填字段）**

- 回答内容；数据来源；未知字段说明（如有）

### 节点⑥ 理赔协办 / 可赔性咨询（LLM 节点）

**目标**：理赔协办——材料引导、完整性校验、发起草稿（需确认）；可赔性咨询——将案情路由至理赔预判 Agent，转述其结构化意见并附免责。

**输入（必填字段）**

- 协办模式：保单信息、理赔类型、已提供材料清单
- 咨询模式：保单信息、案情描述、理赔预判结果（倾向 + 依据 + 置信度，来自理赔预判 Agent）

**处理逻辑** 协办模式：按"理赔类型 → 材料清单"知识库映射给出材料清单（带来源），校验完整性并列缺失项；材料齐全才生成发起草稿并置 need_confirmtrue。咨询模式：可赔性属理赔域专业判断，​**本节点不得自行依据条款判断能否赔付**​——由编排代码将案情摘要（最小字段集）提交理赔预判 Agent，本节点将其返回的结构化意见（倾向/依据/置信度）转述给代理人，强制附免责语（"预判仅供参考，以正式理赔审核结论为准"），并标注来源 claims_agent。理赔预判 Agent 超时/不可用时降级：给出材料准备引导 + 建议咨询理赔专员，不做任何倾向性判断。任何情况下不得声称理赔成功或承诺结果。

**核心系统提示词**

```Plain
你是理赔协办与可赔性咨询模块。
协办规则：
1. 材料清单以知识库检索结果为准，携带来源。
2. 材料不全时只列缺失项，不生成发起草稿。
3. 材料齐全时生成发起请求草稿，need_confirm=true；发起由系统在代理人确认后执行。
咨询规则：
4. 严禁自行依据条款判断可赔性；只转述理赔预判结果（倾向/依据/置信度），来源标注 claims_agent。
5. 转述必须附免责语："预判仅供参考，以正式理赔审核结论为准"。
6. 预判结果缺失时（降级场景），只提供材料准备引导并建议咨询理赔专员，不给倾向性判断。
通用：不得声称理赔成功、不得承诺理赔结果或时效。
```

**输出（必填字段）**

- 协办：材料清单（含来源）、完整性校验与缺失项、发起草稿（齐全时）、need_confirmtrue
- 咨询：预判意见转述（倾向/依据/置信度、来源claims_agent）、免责语

**目标**：生成个性化、无营销的客户关怀文案。

**输入（必填字段）**

- 客户称呼、关怀场景（生日/节日）；代理人风格偏好（如有）

**处理逻辑** 生成 ≤80 字祝福文案，禁止夹带产品、加保、收益等任何营销内容；置 need_confirmtrue，触达经代理人确认。主动链路批量生成时逐条独立生成，保证个性化。

**核心系统提示词**

你是客户关怀文案模块，生成生日/节日祝福。
规则：
1. 文案不超过 80 字，温暖得体、结合客户称呼个性化表达。

### 节点⑧ 合规审查（规则层代码 + 语义层 LLM，全链路强制）

**目标**：对一切将对外展示/发送的内容做合规判定，拦截违规。

**输入（必填字段）**

- 待审内容；内容类型；关联事实来源（涉产品/核保/理赔预判时）

**处理逻辑** 两层串行，任一不过即拦截：

1. **规则层（代码，50ms）** ：关键词/正则匹配硬红线词库（合规部门维护、热更新）：收益承诺类、绝对化用语、贬低同业句式。命中即 reject，附命中词。
2. **语义层（LLM）** ​：判隐晦收益暗示、软性夸大、事实缺来源、缺免责语（可赔性咨询内容额外校验免责语是否存在）。输出 pass / reject / needs_fix 及修改建议，只判定不改写。

**语义层核心系统提示词**

```Plain
你是保险内容合规审查员，对将对外的内容做语义级审查（硬红线已由规则层前置拦截）。
判定项：
1. 隐晦的收益承诺或暗示（如"跑赢通胀没问题""历史从未亏过"）→ reject
2. 软性夸大保障（未用绝对化词但语义夸大）→ needs_fix
3. 贬低同业的暗示性表述 → reject
4. 产品事实/数字/核保/理赔预判表述缺可信来源标注 → needs_fix（标注"需核实"）
5. 缺必要免责/提示语（可赔性咨询必须含"仅供参考，以正式审核为准"）→ needs_fix
输出 verdict（pass/reject/needs_fix）、违规项定位（原文引用）、修改建议。只判定，不改写。
```

**输出（必填字段）**

- verdict；违规项列表（含原文定位）；修改建议

### 节点⑨ 结果组装与风险确认（传统代码，被动链路）

**目标**：组装最终交付内容；高风险操作生成确认卡并管理确认状态。

**输入（必填字段）**

- 已过审的能力节点输出；计划中的高风险标记

**处理逻辑（确定性代码）** 按计划顺序拼装子结果为统一交付卡片；含高风险步骤时生成确认卡（字段：动作类型、目标对象、内容全文、影响说明、确认/取消按钮），任务状态置"待确认"并锁定；确认卡 24 小时未确认自动过期。不含高风险则直接流转交付。

**输出（必填字段）**

- 交付内容；是否需确认；确认卡（如有）；任务状态

### 节点⑩ 交付与记忆写入（传统代码，全链路）

**目标**：交付结果；确认后的高风险操作调用写接口执行；写记忆与审计。

**输入（必填字段）**

- 交付内容；代理人确认结果（高风险场景）；会话与客户标识

**处理逻辑（确定性代码）**

1. 向代理人推送结果卡片。
2. 高风险操作：仅在收到确认事件后调用 submit_claim / send_message，同步写审计（操作人、动作、对象、内容哈希、确认事件 ID、时间、结果回执）；调用失败重试 2 次，仍失败通知代理人并置任务"执行失败"。
3. 记忆写入：本轮对话追加会话记忆；沟通要点、客户新信息按抽取规则写入客户长期画像；代理人对生成内容的编辑行为写入偏好信号。

**输出（必填字段）**

- 交付回执；高风险执行结果与审计 ID（如有）；记忆更新结果

**输出（必填字段）**

- 指标看板；Bad Case 归因记录；优化项清单

1. ## Harness 设计 （第五节课作业参考）

Harness 指模型调用之外、保障系统安全可用的全部外围机制。本章参数为可直接编码的默认值，上线后按数据校准。

### 8.1 记忆与上下文管理

**会话记忆**

- 存储：按会话 ID 存储全量轮次（角色、内容、时间戳、关联任务 ID）。
- 压缩触发：超过 **10 轮**触发滚动摘要——保留​**最近 3 轮原文**，更早轮次压缩为摘要（轻量模型生成，保留：涉及的客户、任务、关键结论、未决事项四类信息）。
- 上下文预算：单次模型调用上限 ​**8,000 tokens**​；超限按优先级裁剪：系统提示词  当前任务数据  最近 3 轮原文  会话摘要  长期记忆。
- 生命周期：**30 分钟**无交互自动归档；归档时触发画像抽取。

**客户长期画像**

- 结构：基础信息（API 只读）+ 沉淀信息（偏好、家庭结构、沟通要点、禁忌话题），沉淀字段带来源会话 ID 与更新时间。
- 写入：会话归档时轻量模型抽取；置信度 0.7 的字段不写入。
- 冲突：新旧值冲突保留双值并标记待代理人确认，不静默覆盖。
- 隔离：按 agent_id 分区存储，查询强制校验归属，跨区在存储层直接拒绝。

**代理人偏好**

- 信号：显式设置（最高优先级）、编辑 diff（编辑率 30% 的句式模式记负偏好）、采纳/拒用行为。
- 生效：偏好摘要注入能力节点上下文；与合规冲突时合规优先。

### 8.2 人机协作

**高风险确认状态机**

- 流转：生成完成 → 待确认 → （确认）已执行 / （取消）已取消 / （超时 ​**24h**）已过期。
- 确认卡必含：动作类型、目标对象（姓名+脱敏标识）、内容全文、影响说明、确认/取消按钮。
- 状态锁：待确认状态下内容不可被覆盖；代理人编辑后须重过节点⑧方可确认。
- 兜底：已过期任务在代理人下次打开 App 时红点提示，可一键重新激活（重新生成并过审）。

**置信度分层**

- **≥0.8** 正常交付；**0.6–0.8** 交付但标注"建议核对后使用"； **0.6** 转草稿模式（明确标注 AI 草稿，需人工修改后才能进入发送/渲染流程）。

**人工接管**

- 任一交付卡片提供"手动编辑"与"转人工处理"入口；转人工后该任务后续步骤停止自动执行。

### 8.3 安全护栏

**输入侧（前置过滤，代码）**

- 风险正则词库热更新，覆盖：收益承诺、编造/篡改条款、跨客户查询句式、跳过确认、批量免确认。
- 频率限制：单代理人 ​**60 次请求/小时**，超限限流提示。
- 隐晦风险由规划 Agent 提示词承担第二道；双层漏检样本回流词库。

**输出侧（节点⑧）**

- 双层串行：规则层（50ms）→ 语义层（LLM）。回炉上限 ​**1 次**；二次不过降级知识库标准话术，样本进 Bad Case 队列。
- 图片素材：generate_image 产出经 OCR 提取文字后过规则层词库。

**工具与外部 Agent 侧（代码）**

- 权限：全部数据工具强制 agent_id 归属校验，失败返回统一错误码并审计。
- 写操作白名单：submit_claim、send_message 仅接受来自节点⑩、携带有效**确认事件 ID** 的调用；缺 ID 在网关层直接拒绝——确认机制由代码保证，不依赖模型自觉。
- 外部 Agent：核保预判超时 ​**8 秒**​、理赔预判同步 **30 秒**转异步；传输字段最小化；调用全量审计（调用方、字段哈希、返回摘要、耗时）；敏感数据不落本产品存储。

**执行侧（编排代码）**

- 步数熔断：单任务模型调用 ​ **≤8 步**​、工具调用 ​ **≤6 次**​、总 Token ​ **≤60,000**，超限中断返回已完成部分。
- 再规划限 ​**1 轮**​；澄清每任务限 ​**1 次**。
- 超时：单节点模型调用 **30 秒**重试 1 次；整任务端到端 ​**3 分钟**。

### 8.4 主动触达调度

- 扫描：每日 **02:00** 全量；续保 ​**T-30 天**​（含当天）入队，生日 **T-3 天**入队。
- 生成：**02:00–06:00** 低峰窗口批量预生成与预审；单代理人单日主动任务上限 ​**20 条**，超出按到期紧急度截断，次日再排。
- 推送：窗口 ​**09:00–20:00**，或代理人打开 App 时即时展示；同一代理人任务合并为日清单卡。
- 触达频控（对客户）：同一客户 ​**7 天内最多 1 次**​、**每月最多 2 次**主动触达；一律经代理人确认。
- 失效：续保任务保单到期后自动关闭；生日任务当日 24:00 过期。

### 8.5 成本与延迟控制

- 模型分层：规划与生成类用主力模型；摘要压缩、画像抽取、澄清语用轻量模型。
- 快路径：简单查询不经规划 Agent，直接取数问答，显著摊薄轻任务成本；短路命中率纳入监控，命中率不足时评估补充小模型路由。
- 缓存：产品条款 RAG 结果按产品 ID 缓存 ​**24 小时**；合规词库与风险正则本地缓存、变更推送刷新。
- 监控：人均日 Token、单任务平均步数、P95 端到端延迟入日报；偏离基线 **20%** 告警。
- 延迟目标：快路径查询 P95 ​ **≤3 秒**​；复杂任务 P95 ​ **≤60 秒**（进度分步反馈，核保预检并行发起）；主动链路推送零生成延迟。
