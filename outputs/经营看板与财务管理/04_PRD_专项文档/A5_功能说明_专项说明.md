# A5 功能说明 — 经营看板 & 财务管理

## 模块一：经营看板

### B1. 核心经营指标

#### 功能目标
页面顶部展示 12 个核心经营指标，每个指标展示数值和环比增长率，支持环比基准切换和时间范围切换，一屏了解业务全貌和变化趋势。

#### 时间筛选

| 选项 | 说明 |
|------|------|
| 今日 | 当天 00:00 至当前时刻 |
| 昨日 | 前一天全天 |
| 本周 | 本周一 00:00 至当前时刻 |
| 本月 | 本月1日 00:00 至当前时刻 |
| 自定义 | 用户自选日期范围 |

> 默认选中"今日"。

#### 环比基准切换

| 选项 | 计算逻辑 |
|------|----------|
| 较昨日 | (今日数据 - 昨日数据) ÷ 昨日数据 × 100% |
| 较上周 | (今日数据 - 上周同一天数据) ÷ 上周同一天数据 × 100% |
| 较上月 | (今日数据 - 上月同一天数据) ÷ 上月同一天数据 × 100% |

> 默认选中"较昨日"。环比基准切换后，所有 12 个指标的环比值同步刷新。

#### 指标展示示例

```
支付金额
¥35,800
↑15.6%
较昨日
```

> 正值绿色箭头向上，负值红色箭头向下。

#### 指标定义

**订单数据（4个）**：

| 指标 | 计算公式 | 数据来源 |
|------|----------|----------|
| 订单数量 | COUNT(时间范围内创建的订单) | 订单系统 |
| 支付订单数量 | COUNT(时间范围内支付成功的订单) | 支付系统 |
| 支付金额(GMV) | SUM(时间范围内支付成功的订单.pay_amount) | 支付系统 |
| 客单价 | 支付金额 ÷ 支付订单数量 | 计算 |

**用户数据（3个）**：

| 指标 | 计算公式 | 数据来源 |
|------|----------|----------|
| 新增用户数 | COUNT(时间范围内注册用户) | 用户系统 |
| 新增会员数 | COUNT(时间范围内开通会员用户) | 用户系统 |
| 活跃用户数 | COUNT(时间范围内有操作的用户) | 用户系统 |

**商品数据（2个）**：

| 指标 | 计算公式 | 数据来源 |
|------|----------|----------|
| 商品销量 | SUM(时间范围内商品订单.quantity) | 订单系统 |
| 商品销售额 | SUM(时间范围内商品订单.pay_amount) | 支付系统 |

**体检数据（2个）**：

| 指标 | 计算公式 | 数据来源 |
|------|----------|----------|
| 体检订单数量 | COUNT(时间范围内体检订单) | 订单系统 |
| 体检销售额 | SUM(时间范围内体检订单.pay_amount) | 支付系统 |

#### 交互规则

| 交互 | 行为 |
|------|------|
| 时间切换 | 所有 12 个指标卡片 + 环比数据同步刷新 |
| 环比基准切换（较昨日/较上周/较上月） | 12 个指标环比值同步刷新 |
| 卡片点击(P1) | 跳转至对应明细页面 |

### B2. 财务趋势

#### 功能目标
以三线折线图展示平台收入变化趋势，区分商品收入、体检收入和总收入。

#### 图表配置

| 属性 | 说明 |
|------|------|
| 图表类型 | 三线折线图 |
| 线1 | 商品收入（蓝色） |
| 线2 | 体检收入（绿色） |
| 线3 | 总收入（橙色/深色） |
| 时间维度 | 日 / 周 / 月 / 年（按钮组切换）+ 时间选择器 |
| 默认维度 | 日 |
| X 轴 | 日期 |
| Y 轴 | 金额(元) |
| 交互 | hover 显示 tooltip（日期 + 商品收入 + 体检收入 + 总收入） |

#### 计算逻辑

| 指标 | 公式 |
|------|------|
| 商品收入 | SUM(统计周期内商品订单实际支付金额) |
| 体检收入 | SUM(统计周期内体检订单实际支付金额) |
| 总收入 | 商品收入 + 体检收入 |

| 属性 | 说明 |

#### 展示示例


| 指标 | 公式 |

### B6. 体检业务分析

#### 功能目标

#### 图表配置

| 属性 | 说明 |
|------|------|
| 图表类型 | 漏斗图 |
| 展示规则 | 按体检订单状态流转展示，超过5个状态时仅保留核心5个节点 |

#### 体检订单状态流转

```
待付款
  ↓
待寄出取样器
  ↓
已收货待检验
  ↓
检验中
  ↓
已完成
  ↓
已退款
```

> 每个阶段展示该状态的订单数量。已退款为退款成功后的终态。

#### 计算逻辑

| 指标 | 公式 |
|------|------|
| 阶段转化率 | 下一阶段数量 ÷ 上一阶段数量 × 100% |

> 漏斗图展示 5 个转化率：待付款→待寄出、待寄出→已收货待检验、已收货待检验→检验中、检验中→已完成、已完成→已退款。

### B9. 订单生命周期

#### 功能目标
在商品订单和体检订单的详情弹窗中，以时间轴形式展示订单从创建、履约到完成，以及退款过程中的完整状态流转记录，支持查看每个状态的变更时间，用于订单追踪、财务核对、结算依据和售后溯源。

#### 功能定位
内嵌于订单详情弹窗中的一个独立模块，展示在当前订单详情信息下方。

#### 商品订单生命周期

**状态流程（5 个核心节点 + 退款分支）**：

```
待付款
  ↓
待发货
  ↓
待收货
  ↓
待评价
  ↓
已完成
  ↓
申请退款   ← 退款分支
  ↓
退款成功
```

> 退款分支仅在订单发生退款时展示。申请退款可从已完成节点后发起。

**展示形式**：纵向时间轴，最新状态在上方。

```
● 退款成功         2026-07-12 16:00
  ↓
● 申请退款         2026-07-12 15:00
  ↓
● 已完成          2026-07-10 15:30
  ↓
● 待评价          2026-07-05 10:20
  ↓
● 待收货          2026-07-02 09:00
  ↓
● 待发货          2026-07-01 14:00
  ↓
● 待付款          2026-07-01 13:50
```

#### 体检订单生命周期

**完整状态（7 个）**：待付款 → 待寄出取样器 → 已寄出取样器 → 待寄出样本 → 已收货待检验 → 检验中 → 已完成

**时间轴展示（保留 5 个核心节点 + 退款分支）**：

```
待付款
  ↓
待寄出取样器
  ↓
已收货待检验
  ↓
检验中
  ↓
已完成
  ↓
申请退款   ← 退款分支
  ↓
退款成功
```

> 已寄出取样器、待寄出样本为中间状态，在时间轴中合并展示，不单独列为节点。退款分支仅在订单发生退款时展示。

**展示形式**：

```
● 退款成功         2026-07-18 16:00
  ↓
● 申请退款         2026-07-18 15:00
  ↓
● 已完成          2026-07-15 16:00
  ↓
● 检验中          2026-07-12 09:30
  ↓
● 已收货待检验     2026-07-10 14:00
  ↓
● 待寄出取样器     2026-07-05 10:00
  ↓
● 待付款          2026-07-05 09:50
```

#### 展示规则

- 所有定义的状态节点均展示在时间轴中
- **已发生**：显示 "● 状态名 + 变更时间"
- **未发生**：显示 "○ 状态名 + 未发生"（空心节点，灰色文字，表示该状态尚未进入）
- 退款分支仅当订单已发起退款时展示，未退款时退款分支的两个节点（申请退款/退款成功）均标记为"未发生"

#### 状态记录规则

| 触发事件 | 记录内容 |
|----------|----------|
| 订单状态变化（含退款） | 新状态名称 + 变更时间（进入该状态的时刻） |

| 字段 | 说明 |
|------|------|
| 订单状态 | 当前进入的状态名称 |
| 变更时间 | 进入该状态的时间；若该状态尚未发生，显示"未发生" |

#### 数据规则

- 订单每次状态变化时，系统自动生成一条生命周期记录
- 数据关联：商品订单 ID / 体检订单 ID
- 按状态流转顺序排列（最新状态在上方），已发生与未发生节点均完整展示
- 用途：订单处理过程追踪、财务核对关键时间节点、供货商/门店结算依据、售后问题追溯

## 模块二：财务管理

> 财务管理为独立一级菜单，下设 3 个二级路由页面：资金概况、财务概览、财务流水。各页面为独立路由，不再使用 Tab 切换。财务报表已并入财务概览，作为其底部的「财务明细报表」区块。

---

### F0. 资金概况

#### 功能目标
回答"现在平台有多少钱？多少钱已被占用？"，区别于财务概览的"最近赚了多少钱"。

> **【口径说明】** 由于商户未接入微信支付商户平台的余额查询接口，本页面不展示微信实时余额，改用「账面余额」——基于平台财务流水自行计算得出。账面余额为业务账面口径，实际到账资金以支付渠道对账单为准。

#### 核心资金指标卡片

| 指标 | 数据来源 | 计算 / 说明 |
|------|----------|-------------|
| **账面余额** | 财务流水系统 | 累计收入 - 累计支出（含退款、提成、供货商/门店货款已结算金额） |
| **待退款金额** | 售后管理 | SUM(退款处理中订单金额) |
| **待供货商结算金额** | 合作管理 → 供货商结算 | SUM(待结算状态的供货商结算金额) |
| **待门店结算金额** | 合作管理 → 门店结算 | SUM(待结算状态的门店结算金额) |
| **待KA服务商提成金额** | 分销/服务商管理 | SUM(一级服务商已产生但未支付的提成金额) |
| **待Pro服务商提成金额** | 分销/服务商管理 | SUM(二级服务商已产生但未支付的提成金额) |

> **服务商层级说明**：服务商分为一级服务商（KA）和二级服务商（Pro），两种提成均纳入资金占用统计。

#### 可用资金

```
账面余额 = 累计收入 - 累计支出
可用资金 = 账面余额 - 待退款 - 待供货商结算 - 待门店结算 - 待KA服务商提成 - 待Pro服务商提成
```

#### 资金趋势

| 属性 | 说明 |
|------|------|
| 图表类型 | 折线图 |
| 数据 | 每日：账面余额、收入金额、支出金额 |
| 时间维度 | 日 / 周 / 月 / 年（按钮组切换）+ 时间选择器 |

#### 资金占用分析

| 属性 | 说明 |
|------|------|
| 图表类型 | 饼图 |
| 数据 | 可用资金 / 供货商结算占用 / 门店结算占用 / 退款占用 / KA服务商提成占用 / Pro服务商提成占用 |

#### 快捷入口

| 点击指标 | 跳转目标 |
|----------|----------|
| 账面余额 | 财务流水 |
| 待退款金额 | 售后管理 |
| 待供货商结算金额 | 合作管理 > 供货商结算 |
| 待门店结算金额 | 合作管理 > 门店结算 |
| 待KA服务商提成金额 | 分销/服务商管理 |
| 待Pro服务商提成金额 | 分销/服务商管理 |

### F1. 财务概览

#### 功能目标
展示平台「已结算」的资金数据（与资金概况的「待结算」对应，此处展示已实际结算/支出后的累计数据）。

> **与资金概况的对应关系**：资金概况展示「待结算/未结算」的占用数据，财务概览展示「已结算」的支出数据，两者的支出项一一对应。

#### 指标卡片

**收入指标（4档：累计/本年/本月/今日）**：

| 指标 | 计算 |
|------|------|
| 累计收入 | SUM(全部历史支付成功订单.pay_amount) |
| 本年收入 | SUM(本年度支付成功订单.pay_amount) |
| 本月收入 | SUM(本月支付成功订单.pay_amount) |
| 今日收入 | SUM(今日支付成功订单.pay_amount) |

**退款指标（4档：累计/本年/本月/今日）**：

| 指标 | 计算 |
|------|------|
| 累计退款 | SUM(全部历史退款成功.refund_amount) |
| 本年退款 | SUM(本年度退款成功.refund_amount) |
| 本月退款 | SUM(本月退款成功.refund_amount) |
| 今日退款 | SUM(今日退款成功.refund_amount) |

**实际收入**：收入 - 退款

| 指标 | 计算 |
|------|------|
| 累计实际收入 | 累计收入 - 累计退款 |
| 本年实际收入 | 本年收入 - 本年退款 |
| 本月实际收入 | 本月收入 - 本月退款 |
| 今日实际收入 | 今日收入 - 今日退款 |

**已结算支出明细（4项，与资金概况待结算项一一对应，不含退款）**：

| 支出项 | 累计 | 本年 | 本月 | 今日 | 对应资金概况项 |
|--------|------|------|------|------|---------------|
| 供货商货款支出 | SUM(全部历史供货商货款已结算) | SUM(本年供货商货款已结算) | SUM(本月供货商货款已结算) | SUM(今日供货商货款已结算) | 待供货商结算 |
| 门店货款支出 | SUM(全部历史门店货款已结算) | SUM(本年门店货款已结算) | SUM(本月门店货款已结算) | SUM(今日门店货款已结算) | 待门店结算 |
| KA服务商提成支出 | SUM(全部历史KA提成已支付) | SUM(本年KA提成已支付) | SUM(本月KA提成已支付) | SUM(今日KA提成已支付) | 待KA服务商提成 |
| Pro服务商提成支出 | SUM(全部历史Pro提成已支付) | SUM(本年Pro提成已支付) | SUM(本月Pro提成已支付) | SUM(今日Pro提成已支付) | 待Pro服务商提成 |

> 退款已在退款指标中单独展示，故已结算支出明细不含退款。

**利润**：

| 指标 | 计算 |
|------|------|
| 累计利润 | 累计实际收入 - 累计已结算支出合计 |
| 本年利润 | 本年实际收入 - 本年已结算支出合计 |
| 本月利润 | 本月实际收入 - 本月已结算支出合计 |
| 今日利润 | 今日实际收入 - 今日已结算支出合计 |

#### 时间筛选（双层控制）

页面顶部设有全局时间筛选器，统一控制下方四个趋势图和财务明细报表；每个图表/报表内又设有独立的局部时间筛选器，可单独覆盖全局设置。

| 层级 | 位置 | 时间维度 |
|------|------|----------|
| 全局时间筛选 | 页面顶部 | [日][周][月][年] + 时间选择器 |
| 局部时间筛选 | 每个图表/报表内 | [日][周][月][年] + 时间选择器 |

> **交互规则**：默认所有图表和财务明细报表跟随全局时间筛选器；当用户切换某个图表/报表的局部时间筛选器时，该图表/报表脱离全局控制，使用自己的时间范围。

#### 财务趋势图（4个）

| 图表 | 类型 | 数据 |
|------|------|------|
| 资金趋势 | 折线图(三线) | 实际收入 / 支出 / 利润。实际收入 = 收入 - 退款；支出 = 各种结算（供货商货款 + 门店货款 + KA提成 + Pro提成），不含退款 |
| 支出趋势 | 折线图(堆叠) | 支出，堆叠分色：供货商货款 / 门店货款 / KA服务商提成 / Pro服务商提成 |
| 退款趋势 | 折线图 | 退款金额（特殊支出，单独展示，不并入支出趋势） |
| 利润趋势 | 折线图 | 利润 = 实际收入 - 支出 |

> 每个趋势图均有自己的局部时间筛选器 [日][周][月][年][时间选择器]，可单独调整。

#### 财务明细报表

> 原「财务报表」功能并入此处，作为财务概览底部的明细报表区块，用于对账和导出。

**统计维度**：

| 维度 | 说明 |
|------|------|
| 按日 | 每日统计 |
| 按月 | 每月统计 |
| 自定义 | 选定时间范围聚合 |

**明细表格字段**：

| 字段 | 计算 |
|------|------|
| 日期/月份 | 统计周期 |
| 订单收入 | SUM(支付金额) |
| 退款金额 | SUM(退款金额) |
| KA服务商提成支出 | SUM(KA服务商提成) |
| Pro服务商提成支出 | SUM(Pro服务商提成) |
| 供货商货款支出 | SUM(供货商货款支出) |
| 门店货款支出 | SUM(门店货款支出) |
| 实际收入 | 订单收入 - 退款金额 |
| 利润 | 实际收入 - KA服务商提成支出 - Pro服务商提成支出 - 供货商货款支出 - 门店货款支出 |

**展示与导出**：
- 明细表格（按日/月列出各项数据）
- 支持导出 Excel（导出当前统计维度和时间范围的报表数据）
