# A5 功能说明 — 经营看板 & 财务管理

## 模块一：经营看板

### B1. 核心经营指标

#### 功能目标
页面顶部展示 12 个核心经营指标，每个指标展示数值和环比增长率，支持环比基准切换和时间范围切换，一屏了解业务全貌和变化趋势。

#### 时间筛选

| 选项 | 说明 |
|------|------|
| 今日 | 当天 00:00 至当前时刻 |
| 昨日 | 前一天全天 |
| 本周 | 本周一 00:00 至当前时刻 |
| 本月 | 本月1日 00:00 至当前时刻 |
| 自定义 | 用户自选日期范围 |

> 默认选中"今日"。

#### 环比基准切换

| 选项 | 计算逻辑 |
|------|----------|
| 较昨日 | (今日数据 - 昨日数据) ÷ 昨日数据 × 100% |
| 较上周 | (今日数据 - 上周同一天数据) ÷ 上周同一天数据 × 100% |
| 较上月 | (今日数据 - 上月同一天数据) ÷ 上月同一天数据 × 100% |

> 默认选中"较昨日"。环比基准切换后，所有 12 个指标的环比值同步刷新。

#### 指标展示示例

```
支付金额
¥35,800
↑15.6%
较昨日
```

> 正值绿色箭头向上，负值红色箭头向下。

#### 指标定义

**订单数据（4个）**：

| 指标 | 计算公式 | 数据来源 |
|------|----------|----------|
| 订单数量 | COUNT(时间范围内创建的订单) | 订单系统 |
| 支付订单数量 | COUNT(时间范围内支付成功的订单) | 支付系统 |
| 支付金额(GMV) | SUM(时间范围内支付成功的订单.pay_amount) | 支付系统 |
| 客单价 | 支付金额 ÷ 支付订单数量 | 计算 |

**用户数据（3个）**：

| 指标 | 计算公式 | 数据来源 |
|------|----------|----------|
| 新增用户数 | COUNT(时间范围内注册用户) | 用户系统 |
| 新增会员数 | COUNT(时间范围内开通会员用户) | 用户系统 |
| 活跃用户数 | COUNT(时间范围内有操作的用户) | 用户系统 |

**商品数据（2个）**：

| 指标 | 计算公式 | 数据来源 |
|------|----------|----------|
| 商品销量 | SUM(时间范围内商品订单.quantity) | 订单系统 |
| 商品销售额 | SUM(时间范围内商品订单.pay_amount) | 支付系统 |

**体检数据（2个）**：

| 指标 | 计算公式 | 数据来源 |
|------|----------|----------|
| 体检订单数量 | COUNT(时间范围内体检订单) | 订单系统 |
| 体检销售额 | SUM(时间范围内体检订单.pay_amount) | 支付系统 |

#### 交互规则

| 交互 | 行为 |
|------|------|
| 时间切换 | 所有 12 个指标卡片 + 环比数据同步刷新 |
| 环比基准切换（较昨日/较上周/较上月） | 12 个指标环比值同步刷新 |
| 卡片点击(P1) | 跳转至对应明细页面 |

### B2. 财务趋势

#### 功能目标
以三线折线图展示平台收入变化趋势，区分商品收入、体检收入和总收入。

#### 图表配置

| 属性 | 说明 |
|------|------|
| 图表类型 | 三线折线图 |
| 线1 | 商品收入（蓝色） |
| 线2 | 体检收入（绿色） |
| 线3 | 总收入（橙色/深色） |
| 时间维度 | 日 / 周 / 月（按钮组切换） |
| 默认维度 | 日 |
| X 轴 | 日期 |
| Y 轴 | 金额(元) |
| 交互 | hover 显示 tooltip（日期 + 商品收入 + 体检收入 + 总收入） |

#### 计算逻辑

| 指标 | 公式 |
|------|------|
| 商品收入 | SUM(统计周期内商品订单实际支付金额) |
| 体检收入 | SUM(统计周期内体检订单实际支付金额) |
| 总收入 | 商品收入 + 体检收入 |

>

### B9. 订单生命周期

#### 功能目标
在商品订单和体检订单的详情弹窗中，以时间轴形式展示订单从创建、履约到完成，以及退款过程中的完整状态流转记录，支持查看每个状态的变更时间，用于订单追踪、财务核对、结算依据和售后溯源。

#### 功能定位
内嵌于订单详情弹窗中的一个独立模块，展示在当前订单详情信息下方。

#### 商品订单生命周期

**状态流程（5 个核心节点 + 退款分支）**：

```
待付款
  ↓
待发货
  ↓
待收货
  ↓
待评价
  ↓
已完成
  ↓
申请退款   ← 退款分支
  ↓
退款成功
```

> 退款分支仅在订单发生退款时展示。申请退款可从已完成节点后发起。

**展示形式**：纵向时间轴，最新状态在上方。

```
● 退款成功         2026-07-12 16:00
  ↓
● 申请退款         2026-07-12 15:00
  ↓
● 已完成          2026-07-10 15:30
  ↓
● 待评价          2026-07-05 10:20
  ↓
● 待收货          2026-07-02 09:00
  ↓
● 待发货          2026-07-01 14:00
  ↓
● 待付款          2026-07-01 13:50
```

#### 体检订单生命周期

**完整状态（7 个）**：待付款 → 待寄出取样器 → 已寄出取样器 → 待寄出样本 → 已收货待检验 → 检验中 → 已完成

**时间轴展示（保留 5 个核心节点 + 退款分支）**：

```
待付款
  ↓
待寄出取样器
  ↓
已收货待检验
  ↓
检验中
  ↓
已完成
  ↓
申请退款   ← 退款分支
  ↓
退款成功
```

> 已寄出取样器、待寄出样本为中间状态，在时间轴中合并展示，不单独列为节点。退款分支仅在订单发生退款时展示。

**展示形式**：

```
● 退款成功         2026-07-18 16:00
  ↓
● 申请退款         2026-07-18 15:00
  ↓
● 已完成          2026-07-15 16:00
  ↓
● 检验中          2026-07-12 09:30
  ↓
● 已收货待检验     2026-07-10 14:00
  ↓
● 待寄出取样器     2026-07-05 10:00
  ↓
● 待付款          2026-07-05 09:50
```

#### 展示规则

- 所有定义的状态节点均展示在时间轴中
- **已发生**：显示 "● 状态名 + 变更时间"
- **未发生**：显示 "○ 状态名 + 未发生"（空心节点，灰色文字，表示该状态尚未进入）
- 退款分支仅当订单已发起退款时展示，未退款时退款分支的两个节点（申请退款/退款成功）均标记为"未发生"

#### 状态记录规则

| 触发事件 | 记录内容 |
|----------|----------|
| 订单状态变化（含退款） | 新状态名称 + 变更时间（进入该状态的时刻） |

| 字段 | 说明 |
|------|------|
| 订单状态 | 当前进入的状态名称 |
| 变更时间 | 进入该状态的时间；若该状态尚未发生，显示"未发生" |

#### 数据规则

- 订单每次状态变化时，系统自动生成一条生命周期记录
- 数据关联：商品订单 ID / 体检订单 ID
- 按状态流转顺序排列（最新状态在上方），已发生与未发生节点均完整展示
- 用途：订单处理过程追踪、财务核对关键时间节点、供货商/门店结算依据、售后问题追溯

### F0. 资金概况

#### 功能目标
回答"现在平台有多少钱？多少钱已被占用？"，区别于财务概览的"最近赚了多少钱"。

#### 核心资金指标卡片

| 指标 | 数据来源 | 计算 / 说明 |
|------|----------|-------------|
| **微信账户余额** | 微信支付商户平台接口 | 平台账户当前余额，含更新时间 |
| **待退款金额** | 售后管理 | SUM(退款处理中订单金额) |
| **待供货商结算金额** | 合作管理 → 供货商结算 | SUM(待结算状态的供货商结算金额) |
| **待门店结算金额** | 合作管理 → 门店结算 | SUM(待结算状态的门店结算金额) |
| **待服务商提成金额** | 分销/服务商管理 | SUM(已产生但未支付的提成金额) |

#### 可用资金

```
可用资金 = 微信账户余额 - 待退款 - 待供货商结算 - 待门店结算 - 待服务商提成
```

| 时间维度 | 日 / 周 / 月 |

#### 资金占用分析

| 属性 | 说明 |
|------|------|
| 图表类型 | 饼图 |
| 数据 | 可用资金 / 供货商结算占用 / 门店结算占用 / 退款占用 / 服务商提成占用 |

#### 快捷入口

| 点击指标 | 跳转目标 |

| 待服务商提成金额 | 分销/服务商管理 |

### F1. 财务概览

#### 功能目标
展示平台资金整体情况，包含指标卡片和趋势图表。

#### 指标卡片

**收入指标（3个）**：

| 指标 | 计算 |
|------|------|
| 累计收入 | SUM(全部历史支付成功订单.pay_amount) |
| 本月收入 | SUM(本月支付成功订单.pay_amount) |
| 今日收入 | SUM(今日支付成功订单.pay_amount) |

**退款指标（3个）**：

| 指标 | 计算 |
|------|------|
| 累计退款 | SUM(全部历史退款成功.refund_amount) |
| 本月退款 | SUM(本月退款成功.refund_amount) |
| 今日退款 | SUM(今日退款成功.refund_amount) |

**合作支出（2个）**：

| 指标 | 计算 |
|------|------|
| 本月合作支出 | SUM(本月供货商货款支出) + SUM(本月门店货款支出) |
| 累计合作支出 | SUM(全部历史供货商货款支出) + SUM(全部历史门店货款支出) |

**实际收入**：累计收入 - 累计退款

**利润**：实际收入 - SUM(服务商提成) - SUM(供货商成本) - SUM(门店成本)

> 服务商提成数据来源于分销管理模块；供货商成本和门店成本数据来源于合作管理结算系统。【本次新增】

#### 财务趋势图（3个）

| 图表 | 类型 | 数据 |
|------|------|------|
| 收入趋势 | 折线图(面积) | 每日收入金额 |
| 支出趋势 | 折线图 | 每日支出（退款 + 服务商提成 + 供货商货款 + 门店货款），堆叠图分色展示 |
| 利润趋势 | 折线图 | 每日(收入 - 支出) |

> 均支持日/周/月时间维度切换。

| 业务类型 | 下拉 | 全部/商品订单收入/体检订单收入/活动订单收入/退款支出/服务商提成支出/供货商货款支出 / 门店货款支出 |
| 订单号搜索 | 文本 | 精确搜索 |

#### 流水生成规则

| 触发事件 | 流水类型 | 业务类型 | 金额 |
|----------|----------|----------|------|
| 商品订单支付成功 | 收入 | 商品订单收入 | +支付金额 |
| 体检订单支付成功 | 收入 | 体检订单收入 | +支付金额 |
| 活动订单支付成功 | 收入 | 活动订单收入 | +支付金额 |
| 用户退款成功 | 支出 | 退款支出 | -退款金额 |
| 服务商提成生成 | 支出 | 服务商提成支出 | -提成金额 |
| 供货商结算记录 | 支出 | 供货商货款支出 / 门店货款支出 | -结算金额 |

### F3. 财务报表

#### 统计维度

| 维度 | 说明 |
|------|------|
| 按日 | 每日统计 |
| 按月 | 每月统计 |
| 自定义 | 选定时间范围聚合 |

#### 统计指标

| 指标 | 计算 |
|------|------|
| 订单收入 | SUM(支付金额) |
| 退款金额 | SUM(退款金额) |
| 服务商提成支出 | SUM(服务商提成) |
| 供货商货款支出 | SUM(供货商货款支出) |
| 门店货款支出 | SUM(门店货款支出) |
| 实际收入 | 订单收入 - 退款金额 |
| 利润 | 实际收入 - 服务商提成支出 - 供货商货款支出 - 门店货款支出 |

#### 展示方式
- 汇总卡片（收入/退款/提成/供货商成本/利润）
- 趋势图（收入 vs 支出 vs 利润）
- 明细表格（按日/月列出各项数据）
- 支持导出 Excel
