## 二、经营看板 API 依赖

| 编号 | API 用途 | 来源系统 | 关键参数 | 返回数据 |
|------|----------|----------|----------|----------|
| D-API-1 | 核心指标聚合 | 订单+支付+用户 | time_range | 12 个指标值 |
| D-API-2 | 订单趋势 | 订单+支付 | time_range, granularity | 日期列表+订单数+支付金额 |
| D-API-3 | 销售趋势+占比 | 支付 | time_range | 商品销售额+体检销售额 |
| D-API-4 | 商品排行 | 订单+支付 | time_range, sort_by, top_n | 排名列表 |
| D-API-5 | 体检套餐排行 | 订单+支付 | time_range, top_n | 排名列表 |
| D-API-6 | 体检状态分布 | 订单 | time_range | 三种状态+数量 |
| D-API-7 | 用户增长趋势 | 用户 | time_range | 日期列表+新增用户数 |
| D-API-8 | 用户来源分析 | 用户 | time_range | 渠道+用户数 |

## 四、数据同步策略

| 策略 | 适用 | 说明 |
|------|------|------|
| **定时预聚合 + 缓存** | 经营看板指标卡片、财务概览指标 | 每 5 分钟预计算缓存，前端直接读取缓存 |
| **API 实时查询** | 财务流水列表、商品排行 | 数据量可控，实时查询 |
| **事件驱动** | 财务流水生成 | 监听支付/退款/提成事件，实时写入流水表 |
| **按需计算** | 财务报表 | 用户选择时间范围后实时聚合计算 |

## 五、财务流水生成机制

```
事件源                  流水生成
─────────────────────────────────────
商品订单支付成功 ──▶ 收入流水（商品订单收入，+金额，含数量）
体检订单支付成功 ──▶ 收入流水（体检订单收入，+金额，含数量）
活动订单支付成功 ──▶ 收入流水（活动订单收入，+金额，含数量）
退款成功事件 ──────▶ 支出流水（退款支出，-金额）
提成生成事件 ──────▶ 支出流水（服务商提成支出，-金额）
供货商结算事件 ────▶ 支出流水（供货商货款支出 / 门店货款支出，-金额）

异常保障：
  定时对账任务 → 对比支付/退款/提成/供货商结算表 vs 流水表
  → 发现缺失 → 补录流水
```

## 六、权限控制流程

```
用户登录
    │
    ▼
获取用户角色权限
    │
    ├── 角色 = 老板/管理 → 经营看板菜单 ✅ + 财务管理菜单 ✅
    ├── 角色 = 运营 → 经营看板菜单 ✅ + 财务管理菜单 ❌
    └── 角色 = 财务 → 经营看板菜单 ❌ + 财务管理菜单 ✅
    │
    ▼
前端菜单渲染（有权限的显示，无权限的隐藏）
    │
    ▼
用户访问 API → 后端校验权限 → 无权限返回 403
```
