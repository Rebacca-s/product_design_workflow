# BRD 业务需求说明 — 经营看板 & 财务管理

## 1. 业务背景

哆爱宠平台已上线商品销售、体检预约、活动报名等业务，日积月累产生了大量经营数据。

**现状问题**：
- **老板看不到经营全貌**：每天卖了多少？用户增长如何？哪款商品卖得好？体检业务履约率怎样？这些信息分散在订单管理、商品管理、用户管理等不同模块，没有一个统一的经营视图
- **财务数据不可视**：平台收入、退款、服务商提成支出分散在支付系统、售后系统、分销系统中，缺乏统一的财务视图和资金流水记录
- **决策靠问人**：老板想知道本周 GMV 趋势，需要找运营手动拉数据；财务想对账，需要跨 3 个系统手动汇总

## 2. 业务目标

| 目标 | 衡量指标 | 目标值 |
|------|----------|--------|
| 经营数据一屏可见 | 核心指标覆盖率 | 订单/用户/商品/体检 100% |
| 财务对账效率提升 | 月度对账耗时 | ≤ 0.5 天 |
| 决策数据自助获取 | 数据查看自助率 | 100%（无需研发拉数据） |

## 3. 目标用户

| 角色 | 核心诉求 | 主要使用模块 |
|------|----------|-------------|
| 老板 | 了解平台整体经营状况、GMV趋势、利润情况 | 经营看板 + 财务管理 |
| 运营人员 | 关注订单/商品/用户增长数据，优化运营策略 | 经营看板 |
| 财务人员 | 查看收入/退款/服务商提成支出/供货商成本，对账导出，管理供货商结算 | 财务管理 + 供货商管理 |
| 管理人员 | 了解各业务线表现和利润 | 经营看板 + 财务管理 |

## 4. 核心价值

- **经营看板**：老板和运营打开一个页面，5 秒内了解平台整体经营状况
- **财务管理**：财务人员一个页面完成对账，不再跨系统手动汇总
- **数据驱动**：商品排行、体检履约状态一目了然，支撑业务决策

## 5. 关键假设与风险

| 类型 | 内容 |
|------|------|
| 假设 | 订单管理、售后管理、分销管理的后台模块已存在，财务管理不重复建设其列表页 |
| 假设 | 用户渠道来源数据已通过某种方式（如二维码参数、分享链接）记录 |
| 风险 | 聚合查询涉及多系统数据，大数据量下需关注查询性能 |
| 风险 | 服务商提成数据来自分销管理模块，需确认该模块的数据接口就绪状态 |
