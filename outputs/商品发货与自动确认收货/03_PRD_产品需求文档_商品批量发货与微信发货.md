# PRD 产品需求文档 — 商品发货与自动确认收货

> 小迭代简化版。

---

## A1-A4（合并）. 需求概述

**现状**：商品订单发货后，用户需主动点击"确认收货"订单才进入待评价。用户未操作则订单长期停在"待收货"。

**本期目标**：

1. 批量发货：运营人员上传Excel批量发货，替代逐单操作
2. 微信发货接口对接：发货时调用微信发货接口，将物流信息同步至微信侧；微信侧接收后可查看物流轨迹，并根据签收状态自动确认收货→系统同步状态→"待评价"

---

## A5. 功能说明

### F1. 商品批量发货

**功能描述**：平台后台商品订单列表新增"批量发货"功能，运营人员通过上传Excel完成批量发货。

**操作流程**：

```
1. 运营人员导出待发货订单Excel（现有功能 + 新增"物流单号"空列）
         ↓
2. 供货商根据订单信息发货，在Excel中填写对应物流单号
         ↓
3. 运营人员在后台商品订单列表页，点击"批量发货"
         ↓
4. 上传供货商填写完成的Excel文件
         ↓
5. 系统解析Excel，校验每一行
         ↓
6. 展示校验结果列表
         ↓
7. 运营人员确认"可发货订单"，点击"立即发货"
         ↓
8. 系统调用微信发货接口同步物流信息，批量更新订单状态 → "待收货"，并记录物流单号
```

**导出Excel新增字段**：

| 字段         | 说明                 | 是否新增 |
| ------------ | -------------------- | -------- |
| 订单编号     | 现有                 | —        |
| 商品名称     | 现有                 | —        |
| 收货人       | 现有                 | —        |
| 收货地址     | 现有                 | —        |
| ...          | 现有                 | —        |
| **物流单号** | **新增，供货商填写** | ✅       |

**校验规则**：

| 校验结果              | 条件                                                  | 处理                           |
| --------------------- | ----------------------------------------------------- | ------------------------------ |
| 可发货                | 订单号匹配 + 状态为"待发货" + 物流单号非空 + 格式正确 | 展示在"可发货"列表             |
| 异常-订单不存在       | Excel中的订单号在系统中不存在                         | 展示在"异常"列表，标注原因     |
| 异常-状态不符         | 订单状态不是"待发货"                                  | 展示在"异常"列表，标注当前状态 |
| 异常-物流单号为空     | 未填写物流单号                                        | 展示在"异常"列表               |
| 异常-物流单号格式异常 | 物流单号不符合快递单号格式                            | 展示在"异常"列表               |

**校验结果页结构**：

```
┌─────────────────────────────────────────────┐
│  批量发货 — 校验结果                          │
│                                              │
│  共上传 50 条，可发货 45 条，异常 5 条          │
├─────────────────────────────────────────────┤
│  ✅ 可发货订单（45条）    [ 一键全部发货 ] │
│  ┌─────────────────────────────────────┐    │
│  │ 订单编号 │ 收货人 │ 物流单号 │ 订单状态 │ 操作    │    │
│  │ DD001   │ 张三   │ SF123.. │ 待发货   │ 立即发货│    │
│  │ DD002   │ 李四   │ YT456.. │ 待发货   │ 立即发货│    │
│  │ ...                                  │    │
│  └─────────────────────────────────────┘    │
├─────────────────────────────────────────────┤
│  ❌ 异常订单（5条）                            │
│  ┌─────────────────────────────────────┐    │
│  │ 订单编号 │ 原因              │ 建议    │    │
│  │ DD099   │ 物流单号为空        │ 补填    │    │
│  │ DD100   │ 订单状态不符（已发货）│ 核实    │    │
│  │ DD101   │ 订单不存在          │ 核对    │    │
│  │ ...                                  │    │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

**发货执行**：

- 单条"立即发货"：仅对该订单执行发货
- "一键全部发货"：对所有可发货订单批量执行
- 发货流程：① 调用微信发货接口同步物流信息 → ② 更新订单状态→"待收货" → ③ 记录物流单号
- 微信发货接口调用失败时：订单状态仍正常更新，但记录失败日志，后台异步重试

**异常处理**：

- 修正Excel后重新上传，每次上传覆盖上一次的校验结果
- 已发货成功的订单在下次上传时会被校验为"状态不符"，避免重复发货

### F2. 微信发货接口对接

**功能描述**：后台确认发货时，调用微信发货接口（微信物流助手），将物流公司、物流单号同步给微信侧，用户在微信内可查看物流轨迹；微信侧根据物流签收状态自动确认收货后，系统同步订单状态。

**核心变动**：现有后台发货按钮仅在本系统内更新订单状态为"待收货"，**未调用微信发货接口**。本次需补齐这一对接。

**微信发货接口调用时机**：

```
运营人员点击"立即发货" 或 "一键全部发货"
    ↓
① 调用微信发货接口（传物流公司 + 物流单号 + 订单信息）
    ↓
② 微信侧接收成功 → 用户微信可查看物流轨迹
    ↓
③ 系统更新订单状态 → "待收货"，记录物流单号
    ↓ （后续由微信侧自动完成）
④ 微信根据物流签收状态，达到自动确认收货时间后自动确认
    ↓
⑤ 系统通过回调/轮询获取微信确认收货状态
    ↓
⑥ 订单状态 → "待评价"（同时触发评价有效期7天计时）
```

**发货接口调用失败处理**：

| 场景                   | 处理方式                                                                   |
| ---------------------- | -------------------------------------------------------------------------- |
| 微信发货接口调用失败   | 订单状态仍正常更新为"待收货"，记录失败日志，后台异步重试（不影响发货流程） |
| 微信发货接口调用超时   | 同上，后台异步补推                                                         |
| 物流单号已被微信侧占用 | 记录异常日志，人工核实                                                     |

**关键原则**：微信发货接口调用不阻断发货流程。发货以系统状态更新为准，微信侧同步失败则异步补推。

**与评价体系的衔接**：

- 微信侧自动确认收货后，系统同步状态→"待评价"
- 用户手动确认收货仍保留（与微信自动确认并行，谁先触发以谁为准）
- 订单进入"待评价"后，评价7天有效期开始计时
- 超期未评价 → 系统自动5星好评 → 已完成
- 售后7天时效同步开始计时

## A8. 异常情况

| 异常                     | 触发条件                            | 处理                                         | 提示                                    |
| ------------------------ | ----------------------------------- | -------------------------------------------- | --------------------------------------- |
| Excel格式错误            | 上传文件不是Excel或列不匹配         | 拒绝上传                                     | "文件格式不正确，请上传正确的Excel文件" |
| 物流单号格式异常         | 单号不符合快递单号规则              | 归入异常列表                                 | "物流单号格式异常"                      |
| 订单已发货               | Excel中的订单已处于待收货或之后状态 | 归入异常列表                                 | "订单状态不符（当前：已发货）"          |
| 订单不存在               | Excel中的订单号在系统不存在         | 归入异常列表                                 | "订单不存在"                            |
| 物流单号为空             | 该行未填写物流单号                  | 归入异常列表                                 | "物流单号为空"                          |
| 微信发货接口调用失败     | 确认发货时调用微信发货接口失败      | 订单状态正常更新，记录失败日志，后台异步重试 | 后台告警，不阻断发货流程                |
| 微信发货接口调用超时     | 微信发货接口响应超时                | 同上，后台异步补推                           | 不阻断发货流程                          |
| 微信确认收货状态同步延迟 | 微信已确认但系统未及时同步          | 定时任务轮询/回调同步                        | 无用户感知                              |

## B3. 状态流转（新增部分）

```
商品订单状态新增流转路径：

原有路径：
待付款 → 待发货 → 待收货（用户手动确认）→ 待评价 → 已完成

新增路径：
待付款 → 待发货 → [调微信发货接口] → 批量发货 → 待收货 → 微信自动确认 → 待评价 → 已完成
                                                              ↘ 用户手动确认 ↗
```

| 流转            | 触发方式            | 触发方   | 关键动作                         |
| --------------- | ------------------- | -------- | -------------------------------- |
| 待发货 → 待收货 | 批量发货 / 单条发货 | 运营人员 | 先调微信发货接口，再更新订单状态 |
| 待收货 → 待评价 | 微信自动确认收货    | 微信同步 | 微信侧签收后自动触发             |
| 待收货 → 待评价 | 用户手动确认收货    | C端用户  | 保留原有手动确认                 |

**微信发货接口调用说明**：

| 项目     | 说明                               |
| -------- | ---------------------------------- |
| 接口     | 微信物流助手 - 发货信息更新接口    |
| 调用时机 | 运营人员确认发货时（单条或批量）   |
| 传参     | 物流公司编码 + 物流单号 + 订单信息 |
| 失败处理 | 不阻断发货流程，异步重试           |

**注意**：手动确认收货仍保留，与微信自动确认并行。谁先触发以谁为准，不重复流转。
