# PRD 产品需求文档 — 商品发货与自动确认收货

> 小迭代简化版。

---

## A1-A4（合并）. 需求概述

**现状**：商品订单发货后，用户需主动点击"确认收货"订单才进入待评价。用户未操作则订单长期停在"待收货"。

**本期目标**：
1. 批量发货：运营人员上传Excel批量发货，替代逐单操作
2. 自动确认收货：接入微信物流接口，微信侧自动确认后系统同步状态→"待评价"

---

## A5. 功能说明

### F1. 商品批量发货

**功能描述**：平台后台商品订单列表新增"批量发货"功能，运营人员通过上传Excel完成批量发货。

**操作流程**：

```
1. 运营人员导出待发货订单Excel（现有功能 + 新增"物流单号"空列）
         ↓
2. 供货商根据订单信息发货，在Excel中填写对应物流单号
         ↓
3. 运营人员在后台商品订单列表页，点击"批量发货"
         ↓
4. 上传供货商填写完成的Excel文件
         ↓
5. 系统解析Excel，校验每一行
         ↓
6. 展示校验结果列表
         ↓
7. 运营人员确认"可发货订单"，点击"立即发货"
         ↓
8. 系统批量更新订单状态 → "待收货"，并记录物流单号
```

**导出Excel新增字段**：

| 字段 | 说明 | 是否新增 |
|------|------|----------|
| 订单编号 | 现有 | — |
| 商品名称 | 现有 | — |
| 收货人 | 现有 | — |
| 收货地址 | 现有 | — |
| ... | 现有 | — |
| **物流单号** | **新增，供货商填写** | ✅ |

**校验规则**：

| 校验结果 | 条件 | 处理 |
|----------|------|------|
| 可发货 | 订单号匹配 + 状态为"待发货" + 物流单号非空 + 格式正确 | 展示在"可发货"列表 |
| 异常-订单不存在 | Excel中的订单号在系统中不存在 | 展示在"异常"列表，标注原因 |
| 异常-状态不符 | 订单状态不是"待发货" | 展示在"异常"列表，标注当前状态 |
| 异常-物流单号为空 | 未填写物流单号 | 展示在"异常"列表 |
| 异常-物流单号格式异常 | 物流单号不符合快递单号格式 | 展示在"异常"列表 |

**校验结果页结构**：

```
┌─────────────────────────────────────────────┐
│  批量发货 — 校验结果                          │
│                                              │
│  共上传 50 条，可发货 45 条，异常 5 条          │
├─────────────────────────────────────────────┤
│  ✅ 可发货订单（45条）                         │
│  ┌─────────────────────────────────────┐    │
│  │ 订单编号 │ 收货人 │ 物流单号 │ 操作    │    │
│  │ DD001   │ 张三   │ SF123.. │ 立即发货│    │
│  │ DD002   │ 李四   │ YT456.. │ 立即发货│    │
│  │ ...                                  │    │
│  └─────────────────────────────────────┘    │
│  [ 一键全部发货 ]                             │
├─────────────────────────────────────────────┤
│  ❌ 异常订单（5条）                            │
│  ┌─────────────────────────────────────┐    │
│  │ 订单编号 │ 原因              │ 建议    │    │
│  │ DD099   │ 物流单号为空        │ 补填    │    │
│  │ DD100   │ 订单状态不符（已发货）│ 核实    │    │
│  │ DD101   │ 订单不存在          │ 核对    │    │
│  │ ...                                  │    │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

**发货执行**：
- 单条"立即发货"：仅对该订单执行发货
- "一键全部发货"：对所有可发货订单批量执行
- 发货后：订单状态→"待收货"，记录物流单号，同步物流信息给微信（F2）

**异常处理**：
- 修正Excel后重新上传，每次上传覆盖上一次的校验结果
- 已发货成功的订单在下次上传时会被校验为"状态不符"，避免重复发货

### F2. 微信自动确认收货

**功能描述**：接入微信物流接口，发货后同步物流信息，微信侧自动完成确认收货后系统同步状态。

**流程**：

```
批量发货成功（F1）
    ↓
系统将物流单号+物流公司同步给微信物流接口
    ↓
用户微信侧可查看物流轨迹
    ↓
微信根据快递签收时间，达到自动确认收货期限后自动确认
    ↓
系统同步微信确认收货状态
    ↓
订单状态 → "待评价"（同时触发评价有效期7天计时）
```

**状态流转**：

```
待发货 ──批量发货──→ 待收货 ──微信自动确认──→ 待评价
                        │
                        └──用户手动确认收货──→ 待评价
```

**与评价体系的衔接**：
- 订单进入"待评价"后，评价7天有效期开始计时
- 超期未评价 → 系统自动5星好评 → 已完成
- 售后7天时效同步开始计时

## A6. 页面改动

### 商品订单列表页（改造）

- 新增"批量发货"按钮（放在导出按钮旁边）
- 点击"批量发货"→ 弹出文件上传区域

### 批量发货校验结果页（新增）

- 临时校验结果页，不持久化
- 左侧"可发货订单"列表 + 右侧"异常订单"列表（或上下布局）
- 每行展示校验状态、订单信息、操作按钮

## A8. 异常情况

| 异常 | 触发条件 | 处理 | 提示 |
|------|----------|------|------|
| Excel格式错误 | 上传文件不是Excel或列不匹配 | 拒绝上传 | "文件格式不正确，请上传正确的Excel文件" |
| 物流单号格式异常 | 单号不符合快递单号规则 | 归入异常列表 | "物流单号格式异常" |
| 订单已发货 | Excel中的订单已处于待收货或之后状态 | 归入异常列表 | "订单状态不符（当前：已发货）" |
| 订单不存在 | Excel中的订单号在系统不存在 | 归入异常列表 | "订单不存在" |
| 物流单号为空 | 该行未填写物流单号 | 归入异常列表 | "物流单号为空" |
| 微信接口同步失败 | 发货后物流信息同步微信失败 | 记录失败日志，后台重试 | 后台告警，不阻断发货流程 |
| 微信确认收货状态同步延迟 | 微信已确认但系统未及时同步 | 定时任务轮询同步 | 无用户感知 |

## A9. 验收标准

- [ ] 商品订单列表展示"批量发货"按钮
- [ ] 导出Excel包含"物流单号"空列
- [ ] 上传Excel后展示校验结果（可发货/异常分开展示）
- [ ] "立即发货"和"一键全部发货"均可正常执行，订单→待收货
- [ ] 发货后物流单号同步至微信侧
- [ ] 微信自动确认收货后，系统订单状态同步→待评价

## B3. 状态流转（新增部分）

```
商品订单状态新增自动流转路径：

原有路径：
待付款 → 待发货 → 待收货（用户手动确认）→ 待评价 → 已完成

新增路径：
待付款 → 待发货 → 批量发货 → 待收货 → 微信自动确认 → 待评价 → 已完成
                                                   ↘ 用户手动确认 ↗
```

| 流转 | 触发方式 | 触发方 |
|------|----------|--------|
| 待发货 → 待收货 | 批量发货（Excel上传） | 运营人员 |
| 待收货 → 待评价 | 微信自动确认收货 | 微信同步 |
| 待收货 → 待评价 | 用户手动确认收货 | C端用户 |

**注意**：手动确认收货仍保留，与微信自动确认并行。谁先触发以谁为准，不重复流转。
