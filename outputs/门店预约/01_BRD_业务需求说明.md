# BRD 业务需求说明 — 多爱宠门店预约

## 1. 业务问题

多爱宠当前小程序仅支持商品寄货和体检线上寄样两种履约方式。虽然部分体检服务已在线下合作医院完成，但系统层面缺乏门店管理、到店自提、线下预约和核销闭环能力。

**当前问题**：

1. **履约方式单一**：商品只能寄货，无法满足用户就近自提的需求（养宠用户往往有即时性需求，如急需宠物药品、食品）。
2. **门店能力缺失**：小程序没有门店列表、门店详情页，用户无法按地理位置发现附近可提供服务的门店。
3. **线下核销无系统支撑**：体检服务虽可到线下医院完成，但缺乏核销码/核销流程，门店与平台的履约确认依赖人工沟通。
4. **门店无法自助管理**：合作医院和第三方体检医院没有后台，无法自主管理营业时间、预约时间、可提供的服务范围。
5. **评价体系缺失**：用户线下体验后无评价入口，门店服务质量无法沉淀为平台数据。

## 2. 不做会怎么样

1. **用户体验落后于竞品**：宠物行业本地化服务趋势明显（宠物医院、宠物店、宠物美容），无门店能力将降低用户留存。
2. **履约效率低**：仅靠寄货无法覆盖时效性需求，用户流失到可到店服务的竞品。
3. **门店合作难以规模化**：没有门店后台支撑，每新增一个合作门店都依赖平台运营人工对接，无法规模扩张。
4. **服务质量不可控**：缺少评价和监督机制，线下门店服务质量无法衡量和改进。

## 3. 目标用户

| 用户群体 | 画像描述 | 核心痛点 |
|----------|----------|----------|
| C端宠物主人 | 25-40岁都市养宠人群，有宠物健康管理意识，习惯使用小程序购物 | 买宠物药品/食品想就近自提；做体检想找附近靠谱的医院 |
| 平台运营人员 | 多爱宠平台运营团队，负责商品、服务和门店的日常管理 | 门店越来越多，人工管理效率低；需要系统化配置和管理门店 |
| 门店工作人员 | 自营门店员工、合作宠物医院前台、第三方体检医院人员 | 没有系统支撑，核销靠人工确认；无法自主管理营业时间和可预约时间 |

## 4. 用户价值

- **C端用户**：可就近自提商品（更快拿到）、可就近预约体检（更便捷）、可查看门店评价选择靠谱门店（更放心）、核销后可在小程序查看体检报告（一站式体验）。
- **门店人员**：通过扫码核销替代人工确认（提效）、可自主维护营业时间和预约时间（灵活）、可管理商品/服务上下架（降低沟通成本）。
- **平台运营**：统一管理所有门店（可规模化）、通过配置而非硬编码给门店分配商品和服务（灵活可扩展）、可监控核销记录和评价（数据驱动运营）。

## 5. 业务价值

- **价值 1：提升转化率**：增加门店自提选项可降低用户因"不想等快递"而放弃购买的比例。
- **价值 2：拓展线下合作**：系统化的门店管理能力是拓展合作医院和第三方门店的基础，有助于平台规模化。
- **价值 3：沉淀门店数据**：通过评价体系和核销记录，积累门店服务质量数据，为后续门店推荐、排名、淘汰提供依据。
- **价值 4：构建O2O闭环**：从线上购买到线下核销再到线上评价/查看报告，形成完整的O2O闭环体验。

## 6. AI 必要性判断

**为什么不需要 AI？**

本次门店预约需求是典型的O2O业务逻辑：门店管理、履约方式选择、预约时间、核销码、评价体系。所有核心功能均可通过规则引擎、状态机和标准CRUD操作完成，不依赖任何AI能力。

**不用 AI 行不行？**

完全可以。功能的复杂点在于多角色权限设计、订单状态流转、多端数据协同，这些都是工程问题而非AI问题。

## 7. 成功标准

- [ ] 用户可在商品详情页选择"门店自提"并完成下单（替代部分寄货订单）
- [ ] 用户可在体检详情页选择"线下门店预约"并选择门店和时间
- [ ] 用户可从门店列表入口浏览附近门店并完成下单
- [ ] 门店人员可通过扫码或输入核销码完成订单核销
- [ ] 核销后订单状态正确流转（待使用→已核销→已完成/报告已上传）
- [ ] 门店可在后台管理本门店的商品/服务上下架
- [ ] 用户核销后可评价门店，评价展示在门店详情页
- [ ] 体检报告上传后用户可在小程序查看

## 8. 假设清单

> 以下为当前基于有限信息做出的假设，请逐一确认：

- 假设 1：门店列表按用户定位距离排序，平台后台可配置排序权重干预排序结果
- 假设 2：预约时间粒度由平台后台统一配置（可选15/30/60分钟）
- 假设 3：核销码为静态码（下单生成后不变），同时支持二维码和数字码
- 假设 4：门店后台为PC Web端
- 假设 5：门店评价采用5星制评分，综合评分为所有评价的算术平均分（保留1位小数）
- 假设 6：一个门店只能核销绑定到本门店的订单
- 假设 7：门店后台账号由平台运营统一创建和分配（待确认）
