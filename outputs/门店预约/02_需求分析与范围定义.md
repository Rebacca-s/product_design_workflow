# 需求分析与范围定义 — 多爱宠门店预约

## 1. 用户角色


| 角色         | 画像描述                     | 核心诉求                               | 使用端口          |
| ---------- | ------------------------ | ---------------------------------- | ------------- |
| C端用户（宠物主人） | 已有多爱宠小程序使用习惯，购买过商品或体检服务  | 希望就近自提商品、就近预约体检、查看门店评价和体检报告        | 小程序           |
| 平台运营人员     | 多爱宠平台运营团队，负责统一管理商品、服务和门店 | 统一管理所有门店、配置门店可售范围、查看核销记录和门店评价      | 平台总后台（PC Web） |
| 门店工作人员     | 自营门店员工、合作医院前台、第三方体检医院人员  | 核销订单、维护门店信息、管理商品/服务上下架、上传体检报告、查看评价 | 门店后台（PC Web）  |


## 2. 使用场景


| 编号  | 场景         | 用户   | 触发条件             | 行为路径                                                 | 期望结果            |
| --- | ---------- | ---- | ---------------- | ---------------------------------------------------- | --------------- |
| S1  | 买商品选门店自提   | C端用户 | 购买商品时希望就近自提取货    | 进入商品详情→选门店自提→选附近门店→确认订单→支付→到店出示核销码→门店核销→取货           | 成功自提取货，订单完成     |
| S2  | 买体检选线下门店预约 | C端用户 | 购买体检服务希望到线下门店完成  | 进入体检详情→选线下门店预约→选门店和到店时间→确认订单→支付→按时到店→出示核销码→门店核销→完成体检 | 成功完成体检，后续可查看报告  |
| S3  | 先找门店再下单    | C端用户 | 想找附近门店，看有什么可买或可约 | 进入门店列表→按距离排序→选门店→看门店详情→选商品/体检→下单（自提或预约）              | 通过门店入口完成购买      |
| S4  | 商品寄货（不变）   | C端用户 | 购买商品希望寄送到家       | 进入商品详情→选线上寄货→填地址→确认订单→支付                             | 等待收货，流程不变       |
| S5  | 体检线上寄样（不变） | C端用户 | 购买体检服务希望在家完成     | 进入体检详情→选线上寄样→填地址→确认订单→支付                             | 等待寄样工具，流程不变     |
| S6  | 到店核销       | 门店人员 | 用户到店出示核销码        | 打开门店后台→扫码或输入核销码→确认订单信息→点击核销                          | 订单核销成功，状态更新     |
| S7  | 上传体检报告     | 门店人员 | 体检订单已核销，用户已完成体检  | 门店后台→找到对应订单→上传体检报告→提交                                | 用户可在小程序查看报告     |
| S8  | 评价门店       | C端用户 | 完成核销后想评价门店服务     | 订单详情→去评价→填评分和内容→上传图片→提交                              | 评价发布成功，展示在门店详情页 |
| S9  | 配置门店可售商品   | 平台运营 | 某门店新开，需配置可售范围    | 平台后台→门店管理→选门店→商品配置→勾选可售商品→保存                         | 门店可售商品生效        |
| S10 | 门店下架缺货商品   | 门店人员 | 某商品库存不足          | 门店后台→商品上下架→找到该商品→下架                                  | 小程序不再展示该商品在此门店  |

## 4. 功能范围

### P0（本期必须）


| 编号  | 功能             | 说明                           |
| --- | -------------- | ---------------------------- |
| F1  | 商品履约方式选择       | 商品详情页增加"线上寄货"和"门店自提"选项       |
| F2  | 体检履约方式选择       | 体检详情页增加"线上寄样体检"和"线下门店预约"选项   |
| F3  | 门店列表           | 小程序新增门店列表页，支持按距离排序、按类型筛选     |
| F4  | 门店详情           | 小程序新增门店详情页，展示门店信息、可售商品、可预约服务 |
| F5  | 门店选择           | 用户选择门店自提或线下预约时，可选择门店         |
| F6  | 预约时间选择         | 体检线下预约时，用户可选择到店时间            |
| F7  | 订单确认页改造        | 根据履约方式动态展示不同内容（地址/门店/预约时间）   |
| F8  | 订单详情页改造        | 门店订单展示门店信息+核销码；体检订单展示预约时间+门店 |
| F9  | 核销码生成          | 支付成功后自动生成二维码+数字核销码           |
| F10 | 核销码展示          | 订单详情页展示核销码，支持放大和截图           |
| F11 | 平台总后台 — 门店管理   | 门店CRUD、门店类型、门店状态管理           |
| F12 | 平台总后台 — 门店商品配置 | 给门店配置可售商品范围                  |
| F13 | 平台总后台 — 门店服务配置 | 给门店配置可预约体检服务范围               |
| F14 | 门店后台 — 订单核销    | 扫码/输入核销码核销，核销前确认订单信息         |
| F15 | 门店后台 — 订单查看    | 查看预约订单和自提订单                  |

## 5. 本期不做什么


| 编号  | 不做什么               | 原因                             |
| --- | ------------------ | ------------------------------ |
| N1  | 门店自行新增商品或服务        | 平台统一管控商品和体检服务池，门店只能在配置范围内管理上下架 |
| N2  | 门店之间调货/库存同步        | 本期聚焦门店履约能力，库存管理留待后续            |
| N3  | 在体检项目下单独做评价        | 评价以门店为单位，避免数据分散（用户需求文档已明确）     |
| N4  | 门店预约取消/改期（用户侧自主操作） | 本期用户如需取消或改期需联系客服，后续版本迭代        |
| N5  | 门店支付（到店付款）         | 本期仅支持线上支付后到店核销                 |
| N6  | 门店预约提醒通知（短信/订阅消息）  | 后续版本迭代，本期不做                    |
| N7  | 数据统计看板             | 属于数据统计需求，不在本期范围                |
| N8  | 埋点设计               | 需求未要求，本期不涉及                    |


## 6. 依赖与前置条件


| 编号  | 依赖项         | 说明                      | 影响范围   |
| --- | ----------- | ----------------------- | ------ |
| D1  | 现有商品和体检服务数据 | 平台已有商品和体检服务池，门店配置依赖现有数据 | 平台后台   |
| D2  | 现有订单系统      | 门店订单需在现有订单基础上扩展履约方式字段   | 小程序+后台 |
| D3  | 现有支付系统      | 支付流程不变，但订单需关联门店和预约时间    | 小程序    |
| D4  | 用户定位能力      | 门店列表按距离排序需要用户授权位置       | 小程序    |
| D5  | 核销码生成服务     | 需开发二维码生成+数字码生成能力        | 后端     |
| D6  | 门店后台账号体系    | 需为每个门店创建登录账号，并与门店绑定     | 平台后台   |


## 7. 关键假设


| 编号  | 假设                          | 待确认方 |
| --- | --------------------------- | ---- |
| H1  | 门店列表优先按距离排序（需用户授权定位），平台后台可配置门店排序权重干预排序结果 | 已确认 |
| H2  | 预约时间粒度由平台后台统一配置（如15/30/60分钟），非固定值 | 已确认 |
| H3  | 同一时段预约名额由门店在后台自行配置 | 已确认 |
| H4  | 核销码为静态码（下单生成后不变），非动态刷新码；同时支持二维码和数字码，避免扫码失败时可手动输入 | 已确认 |
| H5  | 门店后台为PC Web端，门店通过浏览器登录 | 已确认 |
| H6  | 门店评价为5星制评分，门店综合评分 = 所有评价的算术平均分 | 已确认 |
| H7  | 门店后台账号由平台运营统一创建和分配 | 待确认 |
