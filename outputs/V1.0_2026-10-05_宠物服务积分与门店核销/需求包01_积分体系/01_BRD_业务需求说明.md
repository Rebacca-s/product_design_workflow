# BRD 业务需求说明 — 积分体系

## 1. 业务背景与现状

平台已有商城商品、门店/供应商管理、商品与门店/供应商关联、供应商结算、财务管理、经营看板等能力。平台下一步重点发展宠物医疗、体检等线下服务场景，业务模式为：用户通过平台到合作宠物医院消费 → 医院向平台返点 → 平台将部分价值以积分形式返还用户 → 用户继续在平台消费。

**当前痛点**：线下医疗服务产生的利益返还无法与用户后续平台消费连接，缺少一个贯穿「获得—持有—消耗」的激励载体，用户留存、复购、粘性难以提升。

## 2. 目标用户与价值

| 对象 | 价值 |
|------|------|
| C 端用户 | 线下消费后获得可兑换的积分权益，降低二次消费成本 |
| 平台运营 | 拥有可配置的营销激励工具，按策略定向发放/开放积分 |
| 平台（商业） | 打通「线下返利 → 平台消费」闭环，提升留存与 GMV 转化 |

## 3. 业务价值与成功标准

- 用户使用积分后 30 日内复购率提升（具体基线待埋点后补充）。
- 积分发放→消费的核销转化率可追踪。
- 运营可自助完成积分发放，替代线下人工台账。

> 数值基线需运营侧提供历史数据后补充（当前假设：先建立能力，后设目标值）。

## 4. 为什么不需要 AI

本需求为积分账户、发放、流水、兑换抵扣等确定性业务逻辑，不依赖大模型/算法。不做 AI 推荐、智能定价。

## 5. 不做会怎样

- 线下返点无法转成用户权益，返点价值沉没，无法反哺复购。
- 兑换/抵扣规则无法在系统固化，运营效率低、易出错。
- 会员价与积分、优惠券叠加关系混乱，产生资损风险。

## 6. 范围与风险简述

本期聚焦积分账户 + 后台人工发放 + 商品积分配置 + 兑换抵扣（全积分 / 积分+现金）+ 会员价共用 + 优惠券互斥。核心风险为「积分与现金、优惠券的互斥关系」处理不当导致资损，需在结算侧严格校验。
