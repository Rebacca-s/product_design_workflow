# 交付物与章节规划 — 积分体系

## 1. 原始需求

建立平台积分体系：给指定用户发放积分、记录余额、积分兑换商城商品/服务、支持商品配置是否允许积分、支持会员价与积分共用、控制积分与优惠券互斥。当前积分来源主要是线下医疗返点（线下付款未走平台），前期由后台人工发放。兑换比例 1 元 = 10 积分（需后台可配置）。

## 2. 需求类型判断

| 需求类型 | 命中 | 依据 |
|----------|------|------|
| 大功能需求 | 是 | 在现有商城上新增独立积分模块，多页面多角色 |
| 非 AI 功能需求 | 是 | 纯业务逻辑 |
| 后台管理功能需求 | 是 | 积分管理、商品积分配置 |
| 权限/角色需求 | 是 | 运营管理员（积分发放） |
| 状态流转类需求 | 是 | 积分流水、兑换抵扣 |

**综合判断**：大功能 + 非 AI + 后台管理 + 权限/角色 + 状态流转
