# 需求分析与范围定义 — 积分体系

## 1. 用户角色与使用场景

| 角色 | 使用场景 | 核心诉求 |
|------|----------|----------|
| C 端用户 | 查看积分余额与流水；结算时用积分抵扣；兑换商品 | 积分清晰可见、可便捷消费 |
| 运营/管理员（后台） | 给指定用户加/减积分、查看流水、配置商品积分 | 高效、可追溯、防误操作 |
| 财务/风控 | 审核积分发放记录 | 操作留痕、金额可对账 |

## 2. 用户故事

- 作为用户，我可以在「我的-积分」看到当前可用积分、获取/消费记录，并进入积分兑换入口。
- 作为用户，我在结算页可以对「支持积分的商品」选择全积分支付或积分+现金支付，并知晓会员价下的积分抵扣值。
- 作为运营，我可以在后台搜索用户并人工增加/扣减积分，填写原因，系统记录流水与操作人。
- 作为运营，我可以在商品编辑页配置「是否支持积分支付」「是否赠送积分」。

## 3. 功能范围（P0/P1/P2）

### P0（本期必做）

1. 用户积分账户（余额、累计获得、累计消耗）
2. 后台人工增加/扣减积分（含原因、操作记录）
3. 积分流水（变动时间/类型/增减/余额/来源/关联业务/操作人）
4. 商品「是否支持积分支付」配置
5. 积分兑换商品（全积分 / 积分+现金）
6. 会员价使用积分（抵扣基准 = 用户实际享受价格）
7. 积分与优惠券互斥
8. 积分兑换比例后台可配置（当前 1 元 = 10 积分）

### P1（预留能力）

9. 商品「是否赠送积分」配置（本期线上购买体检暂不赠积分）
10. 门店核销数据统计（跨需求包，见需求包02）

### P2 / 后续

- 积分批量导入、积分有效期与过期机制、积分退款返还、积分订单售后规则

## 4. 本期不做什么

- 不做动态金额买单、平台统一收款、自动分账、线下消费自动发积分（均属下一阶段）
- 不做推荐关系积分（规则待确认）
- 不做 Excel 批量导入积分（待确认）

## 5. 依赖与风险

| 依赖/风险 | 说明 |
|-----------|------|
| 依赖已有商城结算能力 | 积分抵扣需接入现有订单结算链路 |
| 依赖会员价能力 | 会员价作为积分抵扣基准 |
| 资损风险 | 积分/优惠券互斥处理不当会导致双重优惠 |
| 财务对账 | 人工发放积分需留痕，供财务核对 |
