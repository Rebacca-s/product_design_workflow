# BRD 业务需求说明 — 门店核销

## 1. 业务背景与现状

平台已有门店/供应商管理、服务商品、商品与门店关联、供应商结算。用户购买「宠物体检」等线下服务商品后，可配置给对应医院结算。但**用户到店使用服务时缺乏核销闭环**——「买了体检之后，目前不知道有没有真正被核销」。

## 2. 目标用户与价值

| 对象 | 价值 |
|------|------|
| C 端用户 | 购买后获得可出示的核销凭证，到店快速核销 |
| 门店/医院 | 通过小程序扫码即可确认核销，操作成本最低 |
| 平台 | 掌握服务履约情况，为供应商结算、门店经营数据提供基础 |

## 3. 业务价值与成功标准

- 服务订单从「已支付」到「已核销」状态可追踪。
- 同一凭证只能成功核销一次，杜绝重复/错店核销。
- 门店核销端只需扫码→校验→确认，无需培训成本。

## 4. 为什么不需要 AI

扫码核销、状态校验、记录留痕均为确定性逻辑，不需要 AI。

## 5. 不做会怎样

- 服务履约无法确认，供应商结算依据缺失。
- 存在凭证被重复使用、跨店冒用风险。
- 无法沉淀门店核销数据。

## 6. 范围与风险

本期仅做轻量核销（凭证生成 + 扫码/手动核销 + 状态 + 防重复 + 记录），不做完整预约系统、不做动态买单、不做完整门店 ERP。核心风险为核销安全（防重复、防错店、防已退款订单核销）。
