# 交付物与章节规划 — 门店核销

## 1. 原始需求

平台已有门店/供应商/服务商品/商品门店关联/供应商结算能力，缺「服务商品线下核销」闭环。本期做轻量门店核销：用户购买线下服务商品后生成核销凭证（二维码+核销码），到店后门店工作人员扫码核销，支持手动输码兜底，防重复/防错店核销，留核销记录。门店端采用小程序形式（仅登录+扫码+确认核销），不做完整预约系统、不做门店 ERP。

## 2. 需求类型判断

| 需求类型 | 命中 | 依据 |
|----------|------|------|
| 大功能需求 | 是 | 新增核销模块，多端多角色 |
| 非 AI 功能需求 | 是 | 纯业务逻辑 |
| 后台管理功能需求 | 是 | 核销记录查看 |
| 权限/角色需求 | 是 | 门店核销员 |
| 状态流转类需求 | 是 | 核销凭证状态机 |

**综合判断**：大功能 + 非 AI + 后台管理 + 权限/角色 + 状态流转
