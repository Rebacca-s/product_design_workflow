# 需求分析与范围定义 — 门店核销

## 1. 用户角色与使用场景

| 角色 | 场景 | 诉求 |
|------|------|------|
| C 端用户 | 查看核销凭证/二维码，到店出示 | 凭证清晰可出示 |
| 门店核销员 | 登录门店端，扫码/输码核销 | 轻量、快速、防错 |
| 后台运营 | 查看核销记录 | 掌握履约与结算依据 |

## 2. 用户故事

- 作为用户，购买线下服务商品后可在订单/凭证页查看核销二维码+核销码。
- 作为门店核销员，用小程序扫码后能看到待核销的用户/商品/订单/状态，确认后完成核销。
- 作为后台运营，可查看门店核销记录（门店/订单/商品/用户/时间/状态）。

## 3. 功能范围

### P0（本期必做）

1. 服务商品生成核销凭证（二维码+核销码）
2. 用户查看核销凭证
3. 门店小程序登录/识别门店
4. 扫码核销（主路径）
5. 手动输入核销码（兜底路径）
6. 核销状态（待使用/已核销/已失效/已退款）
7. 防重复核销、防错门店核销
8. 核销记录留痕

### P1（预留）

9. 门店核销数据统计

### 后续 / 不做

- 完整门店预约系统（本期不做）
- 动态金额买单、平台收款、自动分账（下一阶段）

## 4. 本期不做什么

- 不做预约日期/时段/排班/容量/取消/改期
- 不做完整门店 ERP/SaaS
- 不做动态金额买单

## 5. 依赖与风险

| 依赖/风险 | 说明 |
|-----------|------|
| 依赖已有订单/商品/门店 | 核销凭证关联订单与门店 |
| 核销安全 | 防重复、防错店、防已退款/取消订单核销 |
| 账号体系 | 门店核销员账号体系【待确认】 |
