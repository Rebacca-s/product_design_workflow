## 一、功能清单

| 编号 | 功能 | 优先级 | 端口 |
|------|------|--------|------|
| F1 | 生成核销凭证 | P0 | 系统自动 |
| F2 | 用户查看核销凭证 | P0 | 用户端 |
| F3 | 门店端登录/识别门店 | P0 | 门店小程序 |
| F4 | 扫码核销（主路径） | P0 | 门店小程序 |

## 二、功能详细说明

### F1 生成核销凭证

- **触发**：用户购买线下服务商品，订单支付成功后自动生成。
- **内容**：唯一核销二维码 + 数字核销码 + 商品名称 + 使用门店 + 使用状态。
- **唯一性**：一个订单对应一个凭证，核销码全局唯一。

### F2 用户查看核销凭证

- **位置**：订单详情页 / 独立「核销凭证」页（【待确认】最终入口）。
- **展示**：二维码（大）、核销码（数字，可复制）、商品名、使用门店、状态标签。

### F3 门店端登录/识别门店

- **形态**：小程序。
- **账号体系**：【已确认】后台预建门店账号（平台统一创建核销员账号并绑定门店），门店端账号密码登录。
- **流程**：门店核销员登录 → 系统识别其所属门店（及所属连锁主体）→ 进入核销首页（含「扫码核销」入口）。
- **待确认**：核销员数量上限（见 PRD 待确认 17）。

### F4 扫码核销（主路径）

- **流程**：扫码 → 系统解析 → 校验 → 展示待核销信息 → 确认 → 完成。
- **校验项**：
  1. 凭证是否存在、核销码有效；
  2. 订单状态（已支付且未退款/未取消）；
  3. 凭证是否已核销；
  4. 凭证所属门店的「连锁主体」= 当前门店的「连锁主体」（允许连锁门店互核，防非同连锁门店）；
  5. 商品类型为线下服务商品。
- **结果展示**：核销成功 / 已核销 / 无效核销码 / 非本连锁门店商品 / 订单异常。

### F5 手动输入核销码（兜底）

- **触发**：扫码失败等异常场景。
- **交互**：门店端提供「手动输入」入口，输入数字核销码后走与扫码相同的校验与核销流程。

### F6 核销状态管理

| 状态 | 含义 |
|------|------|
| 待使用 | 已支付、未核销 |
| 已核销 | 已完成核销 |
| 已失效 | 过期/作废（规则待确认） |
| 已退款/已取消 | 订单退款或取消后不可核销 |

### F7 防重复/防错店核销

- 同一凭证只能成功核销一次（幂等）。
- 已核销凭证再次扫码 → 提示「已核销」。
- 【已确认】允许连锁门店互核：凭证所属门店与当前门店属于同一「连锁主体」→ 允许核销；非同连锁主体 → 提示「非本连锁门店商品」。
- 「连锁主体/品牌」界定【待确认】：门店与供应商是两个独立概念，核销主体是门店；连锁主体为门店级「品牌/连锁」归属字段（当前假设：门店新增「品牌/连锁」字段）。

### F8 核销记录留痕

- **记录字段**：核销时间、实际核销门店、核销人员、核销订单、核销商品（跨店核销时「实际核销门店」可能 ≠ 凭证原门店，两者均需记录）。
- **用途**：供应商结算依据、门店经营数据基础。
