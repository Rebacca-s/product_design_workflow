# PRD 产品需求文档 — 元梦录音笔记国内外市场适配

> 文档定位：研发交付总装文档。本次仅从产品经理视角定义国内外市场适配下的用户使用规则、产品交互与业务规则。
> 明确不涉及：数据库设计、服务器架构、云厂商选择、接口设计、数据路由技术方案、CDN、多区域容灾、GDPR 条文、海外具体价格。

---

## A1. 需求背景

元梦录音笔记当前的产品功能主要按照中国大陆市场设计。后续产品计划同时面向中国大陆和海外市场，因此需要优先完成以下三个基础模块的国内外适配：

1. **登录与账号体系**
2. **支付与会员购买**
3. **数据存储区域**

国内版和海外版继续使用**同一套核心产品能力和会员体系**，但根据不同市场提供不同的登录方式、支付方式、价格展示与数据存储区域。

---

## A2. 需求目标

### 目标

| 编号 | 目标 | 衡量标准 |
|------|------|----------|
| G1 | 国内、海外提供各自适配的登录入口与登录方式 | 用户可用对应市场的登录方式正常登录 |
| G2 | 同一账号支持绑定多个登录方式，任一方式均可进入原账号 | 换登录方式后录音/知识库/会员权益不丢失 |
| G3 | 建立账号地区概念，区分国内市场与海外市场用户 | 用户有明确、可见的账号地区，且不随 IP/地理位置漂移 |
| G4 | 国内、海外提供各自适配的支付方式与价格展示 | 用户可用对应市场的支付方式购买会员 |
| G5 | 会员权益归属于账号而非设备或登录方式 | 换手机/重装/换登录方式后权益保持不变 |
| G6 | 国内、海外数据分区域存储 | 国内用户数据落国内区域，海外用户数据落海外区域 |
| G7 | 设置页可见数据存储地区与账号地区 | 用户可在设置中查看，无需切换 |

### 保证不丢失

- 用户更换设备后，账号数据不丢失
- 用户更换登录方式后，原有数据不丢失
- 用户会员权益不因更换设备或登录方式而丢失
- 用户录音、知识库、设备绑定等内容始终归属于同一个账号

## A3. 用户角色与使用场景

| 角色 | 画像 | 核心诉求 |
|------|------|----------|
| 国内用户 | 使用中国大陆版元梦录音笔记的用户 | 用手机号/微信/Apple 登录，微信/支付宝购买会员，数据存储在国内 |
| 海外用户 | 使用海外版元梦录音笔记的用户 | 用 Email/Google/Apple 登录，Google Play/Apple 购买会员，数据存储在海外 |
| 跨境用户 | 出差、旅游、使用 VPN 的用户 | 保持原账号地区不变，权益与数据归属不受地理漂移影响 |

| 场景 | 用户 | 触发条件 | 行为路径 | 期望结果 |
|------|------|----------|----------|----------|
| 多登录方式绑定 | 任意 | 用户想用新登录方式登录原账号 | 设置 → 账号与安全 → 未绑定方式「去绑定」→ 完成绑定 → 用新方式登录 | 进入原账号，数据不变 |
| 换手机 | 任意 | 换新设备后首次登录 | 用已绑定任一登录方式登录 | 数据与会员权益完整恢复 |
| 恢复购买 | 海外 | 重装 App 或换设备后会员未同步 | 会员页/设置页 → Restore Purchases | 同步 Apple/Google Play 订阅权益 |
| 跨境出差 | 国内 | 在国外出差期间使用 App | 正常使用，无需操作 | 账号地区仍为中国大陆，数据仍落国内 |
| 购买 YMCard | 任意渠道 | 购买并绑定符合条件的 YMCard | 绑定设备 | 获得 Plus 权益，与销售渠道无关 |
| 查看数据存储地区 | 任意 | 想了解自己数据存放区域 | 设置 → 隐私与数据 | 看到数据存储地区 |

## A5. 功能需求

### 5.1 登录与账号体系

#### 5.1.1 国内市场登录方式

| 登录方式 | 是否主要入口 | 说明 |
|----------|-------------|------|
| 手机号登录 | 是 | 国内主要入口，输入手机号后支持**验证码登录**和**密码登录**两种方式 |
| 微信登录 | 是 | 国内主要入口 |
| Apple 登录 | 是 | iOS |
| 邮箱登录 | 否 | 保留为其他登录方式，不作为国内主要入口 |

**手机号密码登录规则**

- **设置密码**：首次注册（验证码登录）时可选择设置密码；已注册用户可在「账号与安全 → 手机号 → 设置密码」补设。【本次新增】
- **忘记密码**：登录页提供「忘记密码」入口，通过手机号验证码验证后重置密码。【本次新增】
- **密码安全**：密码需满足基本强度要求；连续多次密码错误后临时锁定，防止暴力破解。【当前假设】

#### 5.1.2 海外市场登录方式

| 登录方式 | 是否第一版核心 | 说明 |
|----------|---------------|------|
| Email 邮箱验证码 | 是 | 邮箱 + 验证码，暂不增加邮箱密码体系 |
| Google 登录 | 是 | 海外第一版核心 |
| Apple 登录 | 是 | 海外第一版核心 |
| 国际手机号登录 | 否 | 暂不作为海外第一版核心功能，可后续扩展 |

#### 5.1.3 多登录方式绑定

- 同一个用户账号可以绑定多个登录方式：手机号、Email、微信、Google、Apple。
- 用户后续使用已绑定的**任一登录方式**登录，都应进入**原有账号**。
- 原账号的录音、知识库、AI 分析内容、YMCard 设备、会员权益均保持不变。

#### 5.1.4 防止重复账号

- 产品需避免用户因使用不同登录方式而无意中创建多个账号。
- **不同第三方登录账号不得仅根据邮箱相同就自动合并。**
- 用户希望将新登录方式关联到原账号时，应通过「账号与安全」主动完成绑定。

### 5.2 账号与安全

设置中新增「账号与安全」，支持查看和管理：

| 项目 | 展示/操作 |
|------|-----------|
| 手机号 | 已绑定 / 去绑定 |
| 邮箱 | 已绑定 / 去绑定 |
| 微信 | 已绑定 / 去绑定 |
| Google | 已绑定 / 去绑定 |
| Apple | 已绑定 / 去绑定 |
| 账号地区 | 只读展示（如：中国大陆 / United States） |
| 注销账号 | 入口 |

- 已绑定的登录方式显示「已绑定」；未绑定的登录方式显示「去绑定」。
- 已绑定的登录方式支持「解绑」；解绑后该登录方式不再用于登录原账号，但原账号的录音、知识库、会员权益等数据仍归属于原账号，不因解绑而丢失。【本次新增】
- 已绑定手机号支持「设置密码 / 修改密码」，用于密码登录。【本次新增】

### 5.3 账号地区

#### 5.3.1 概念

每个用户拥有一个账号所属地区，用于判断该用户属于国内市场还是海外市场。

账号地区**不直接绑定**：当前 IP、当前所在国家、出差、旅游、VPN。

> 示例：中国用户去美国出差，不应因此自动变成美国区账号。【示例】

#### 5.3.2 确定方式

- 第一版在用户**首次注册时**确定账号地区。
- 判定依据（按优先级）：① App 包版本（国内版/海外版）；② 注册方式；③ 注册国家或地区。
- 账号地区在注册完成时固化，此后不再随 IP/地理位置/登录方式变化。

> 推荐判定顺序：【当前假设】首次注册时优先以「用户进入的 App 版本（国内版 or 海外版）」为第一判定依据，注册方式、注册国家或地区作为辅助校验；注册完成后账号地区固化。具体最终判定规则由产品与研发后续确认。【待确认】

#### 5.3.3 修改规则

- 第一版用户**不可自行修改**账号地区。
- 设置页可展示：`账号地区：中国大陆` 或 `Account Region: United States`。
- 后续如有需要，再单独设计账号地区迁移功能。

### 5.4 支付与会员购买

#### 5.4.1 支付方式矩阵

| 市场 | 平台 | 支付方式 |
|------|------|----------|
| 国内 | iOS | Apple 内购 |
| 国内 | Android | 微信支付、支付宝 |
| 海外 | iOS | Apple 内购 |
| 海外 | Android | Google Play |

- 海外第一版暂不增加其他第三方支付方式。

#### 5.4.2 会员体系

- 国内版和海外版继续使用**同一套会员等级**：Free、Plus、Pro、Ultra。
- 会员核心权益原则上保持一致。
- 不同地区允许存在不同价格。

> 示例：中国 Pro ¥58/月；美国 Pro $X.XX/month；日本 Pro ¥X,XXX/month。【示例】海外价格后续单独制定。【待确认】

### 5.5 会员与账号绑定规则

会员权益归属于**用户账号**，而不是某一台手机或某一种登录方式。

用户出现以下情况时，只要最终进入的是同一个账号，会员权益必须保持不变：

- 换手机
- 卸载重新安装
- 手机号登录改为 Google 登录
- Google 登录改为 Apple 登录

### 5.6 恢复购买（Restore Purchases）

- 海外版会员页或设置页增加 `Restore Purchases`（恢复购买）。
- 主要用于 Apple 和 Google Play 用户恢复已有订阅或购买权益。
- 用户重新安装 App 或更换设备后，可通过恢复购买重新同步会员状态。

#### 国内会员恢复

- 国内版会员（微信/支付宝购买）不依赖应用商店订阅，会员权益随账号同步。
- 国内用户换设备/重装后，登录原账号即自动同步会员权益，无需手动恢复购买。【当前假设】

### 5.7 YMCard 赠送 Plus

- YMCard 当前权益规则保持不变：购买并成功绑定符合条件的 YMCard 后，用户获得 Plus 会员权益。
- 该权益与购买 YMCard 的**销售渠道无关**。
- 用户通过淘宝、京东、官网、Amazon、海外经销商等渠道购买 YMCard，只要设备符合激活条件，都可正常获得 Plus。

### 5.8 数据存储区域

#### 5.8.1 基本原则

- 国内用户和海外用户的数据需要支持分区域存储。
- 产品经理只定义数据分区规则，不定义具体服务器、云厂商和技术方案。

#### 5.8.2 分区规则

| 用户类型 | 数据存储区域 |
|----------|--------------|
| 国内用户（中国大陆） | 国内数据存储区域 |
| 海外用户 | 海外数据存储区域 |

第一阶段只区分「中国大陆 / 海外」两档；后续随欧洲、美国、日本等市场规模扩大，再根据实际情况进一步细分。

> 未登录/游客状态：第一版默认要求用户登录后才能使用录音笔记核心功能；如需支持游客模式，游客数据不产生或按用户后续登录的账号地区归属。【当前假设】

#### 5.8.3 分区域存储的数据范围

以下数据按用户地区分区存储：

- 原始录音
- 转写文本
- 翻译文本
- AI 分析结果
- 知识库
- 用户上传文件
- 聊天记录
- 声纹相关数据

## A6. 页面与交互说明

> 本节为 5 个页面的完整设计说明，每个页面覆盖：页面结构、信息层级、组件、交互、页面状态、异常情况。

### 6.1 国内登录页

**页面目标**：国内用户首次进入或未登录时，用手机号/微信/Apple 快速登录进入原账号。

**页面结构（从上到下）**

```
┌─────────────────────────┐
│   品牌 Logo / 产品名     │  ← 品牌区
├─────────────────────────┤
│  [手机号登录]            │  ← 主入口（验证码 / 密码两种方式）
│  [微信登录]              │  ← 主入口
│  [Apple 登录]（仅 iOS）  │  ← 主入口
├─────────────────────────┤
│  「其他登录方式」        │
│  [邮箱登录]              │  ← 次级入口（弱化样式）
├─────────────────────────┤
│  登录即代表同意《用户协议》│  ← 协议提示
└─────────────────────────┘
```

**信息层级**：手机号登录 > 微信 > Apple > 邮箱（其他方式折叠或弱化）。

**组件清单**

| 组件 | 位置 | 说明 |
|------|------|------|
| Logo/产品名 | 顶部 | 品牌识别 |
| 「手机号登录」按钮 | 主按钮位 | 点击进入手机号登录表单，可在「验证码登录」与「密码登录」之间切换 |
| 「微信登录」按钮 | 主按钮位 | 拉起微信授权 |
| 「Apple 登录」按钮 | 主按钮位 | 拉起 Apple 授权（仅 iOS 展示） |
| 「其他登录方式」折叠入口 | 中部 | 展开显示邮箱登录 |
| 「邮箱登录」按钮 | 折叠区 | 进入邮箱 + 验证码表单 |
| 协议提示文本 | 底部 | 登录即同意《用户协议》《隐私政策》 |

**交互规则**

1. 点击「手机号登录」→ 输入手机号 → 选择登录方式：
   - **验证码登录**：获取验证码 → 输入验证码 → 登录成功进入账号。
   - **密码登录**：输入密码 → 登录成功进入账号；提供「忘记密码」入口，通过验证码重置密码。
2. 点击「微信登录」→ 拉起微信授权 → 授权成功进入账号。
3. 点击「Apple 登录」→ 拉起 Apple 授权 → 授权成功进入账号。
4. 首次用某方式登录时，按 5.3.2 判定并固化账号地区。

**页面状态**

| 状态 | 触发 | 展示 |
|------|------|------|
| 默认 | 进入页面 | 完整展示所有登录入口 |
| 加载 | 点击登录方式/验证码发送中 | 按钮 loading，验证码倒计时 |
| 空 | — | 不涉及 |
| 错误 | 验证码错误/密码错误/授权取消 | 提示「验证码错误，请重新输入」/「密码错误」/「授权已取消」 |
| 边界 | 频繁请求验证码 | 验证码按钮置灰并倒计时，防刷 |

### 6.2 海外登录页

**页面目标**：海外用户首次进入或未登录时，用 Google/Apple/Email 快速登录。

**页面结构（从上到下）**

```
┌─────────────────────────┐
│   品牌 Logo / 产品名     │  ← 品牌区
├─────────────────────────┤
│  [Continue with Google] │  ← 主入口
│  [Continue with Apple]  │  ← 主入口
├─────────────────────────┤
│  ────────── or ───────── │  ← 分隔
│  [Email 输入框]          │  ← 邮箱 + 验证码登录
│  [Continue]             │  ← 提交按钮
├─────────────────────────┤
│  登录即同意《Terms》《Privacy》│  ← 协议提示
└─────────────────────────┘
```

**信息层级**：Continue with Google / Continue with Apple 并列为主入口，Email 登录为次入口。

**组件清单**

| 组件 | 位置 | 说明 |
|------|------|------|
| Logo/产品名 | 顶部 | 品牌识别 |
| 「Continue with Google」按钮 | 主按钮位 | 拉起 Google 授权 |
| 「Continue with Apple」按钮 | 主按钮位 | 拉起 Apple 授权 |
| 分隔符「or」 | 中部 | 区分第三方与邮箱登录 |
| Email 输入框 | 中部 | 输入邮箱 |
| 「Continue」按钮 | Email 下方 | 发送验证码并进入验证码校验 |
| 协议提示文本 | 底部 | 登录即同意 Terms / Privacy |

**交互规则**

1. 点击「Continue with Google」→ 拉起 Google 授权 → 进入账号。
2. 点击「Continue with Apple」→ 拉起 Apple 授权 → 进入账号。
3. 输入 Email → 点击「Continue」→ 发送邮箱验证码 → 输入验证码 → 登录成功（不建立密码，见 5.1.2）。

**页面状态**

| 状态 | 触发 | 展示 |
|------|------|------|
| 默认 | 进入页面 | 完整展示所有登录入口 |
| 加载 | 授权中/验证码发送中 | 按钮 loading，验证码倒计时 |
| 空 | Email 未输入 | 「Continue」按钮置灰不可点 |
| 错误 | 邮箱格式错误/验证码错误 | 提示「Invalid email」「Invalid code」 |
| 边界 | 频繁请求验证码 | 验证码按钮置灰并倒计时 |

### 6.3 账号与安全页

**页面目标**：用户查看并管理已绑定的登录方式、账号地区，执行解绑与注销。

**页面结构（从上到下）**

```
┌─────────────────────────┐
│  账号地区                 │  ← 只读信息区
│  中国大陆（或 United States）│
├─────────────────────────┤
│  登录方式（分组）          │
│  手机号     [已绑定/去绑定] │
│  邮箱       [已绑定/去绑定] │
│  微信       [已绑定/去绑定] │
│  Google     [已绑定/去绑定] │
│  Apple      [已绑定/去绑定] │
├─────────────────────────┤
│  [注销账号]              │  ← 危险操作区
└─────────────────────────┘
```

**信息层级**：账号地区（只读）> 登录方式绑定列表 > 注销账号（危险区，置底）。

**组件清单**

| 组件 | 位置 | 说明 |
|------|------|------|
| 账号地区展示 | 顶部 | 只读，如「账号地区：中国大陆」/「Account Region: United States」 |
| 登录方式列表 | 中部 | 手机号/邮箱/微信/Google/Apple 各一行 |
| 状态标签 | 每行右侧 | 「已绑定」/「去绑定」 |
| 「去绑定」入口 | 未绑定行 | 点击进入对应绑定流程 |
| 「解绑」入口 | 已绑定行 | 点击弹出解绑确认 |
| 「注销账号」按钮 | 底部 | 红色危险样式，点击进入注销流程 |

**交互规则**

1. 账号地区只读展示，不可点击修改。
2. 未绑定方式显示「去绑定」→ 点击进入对应第三方授权或验证码绑定流程。
3. 已绑定方式显示「已绑定」，点击展开可「解绑」→ 二次确认后解绑，数据仍归原账号（R14）。
4. 「注销账号」→ 二次确认 → 注销，会员权益终止（R15）。

**页面状态**

| 状态 | 触发 | 展示 |
|------|------|------|
| 默认 | 进入页面 | 展示账号地区 + 绑定列表 |
| 加载 | 绑定/解绑请求中 | 对应行 loading |
| 空 | — | 不涉及（登录方式项固定 5 项） |
| 错误 | 绑定失败/该方式已绑其他账号 | 提示「该登录方式已绑定其他账号」 |
| 边界 | 解绑最后一个登录方式 | 提示「至少保留一种登录方式」并阻止 |

### 6.4 会员购买页

**页面目标**：用户查看会员等级与当地价格，通过对应支付方式购买/恢复会员。

**页面结构（从上到下）**

```
┌─────────────────────────┐
│  会员等级卡片            │  ← Free / Plus / Pro / Ultra
│  （价格按地区展示）       │
├─────────────────────────┤
│  价格与权益              │
│  Pro  ¥XX/月（中国，示例）│
│  Pro  $X.XX/month（美国，示例）│
├─────────────────────────┤
│  支付方式                │
│  国内 Android：微信/支付宝│
│  海外 Android：Google Play│
│  iOS：Apple 内购        │
├─────────────────────────┤
│  [Restore Purchases]    │  ← 仅海外版展示
└─────────────────────────┘
```

**信息层级**：会员等级卡片 > 价格/权益 > 支付方式 > 恢复购买。

**组件清单**

| 组件 | 位置 | 说明 |
|------|------|------|
| 会员等级卡片 | 顶部 | Free/Plus/Pro/Ultra，当前等级高亮 |
| 价格展示 | 卡片内 | 按账号地区展示当地价格（货币符号+金额+周期） |
| 权益列表 | 卡片内 | 各等级核心权益对比 |
| 支付按钮 | 底部 | 按「市场 × 平台」展示（微信/支付宝/Google Play/Apple 内购） |
| 「Restore Purchases」 | 底部 | 仅海外版展示，恢复 Apple/Google Play 订阅 |

**交互规则**

1. 选择会员等级 → 点击支付按钮 → 拉起对应支付（微信/支付宝/Google Play/Apple 内购）→ 支付成功 → 会员权益即时生效。
2. 海外用户点击「Restore Purchases」→ 校验 Apple/Google Play 订阅 → 恢复会员权益。
3. 国内用户换设备/重装后登录即自动同步会员（5.6），无需手动恢复。

**页面状态**

| 状态 | 触发 | 展示 |
|------|------|------|
| 默认 | 进入页面 | 展示全部等级与当地价格 |
| 加载 | 价格/订阅状态拉取中 | 骨架屏或 loading |
| 空 | — | 不涉及 |
| 错误 | 支付失败/恢复失败 | 提示「支付未完成，请重试」/「无待恢复的购买记录」 |
| 边界 | 已是最高等级 | 更高等级按钮提示「已是当前等级」 |

## A8. 异常场景

| 编号 | 场景 | 处理 |
|------|------|------|
| E1 | 用户用未绑定的新登录方式登录 | 系统判定为新账号风险；引导用户如需关联原账号，到「账号与安全」主动绑定，不自动合并 |
| E2 | 用户换手机/重装 App 后会员未同步 | 通过 `Restore Purchases` 重新同步 Apple/Google Play 订阅权益 |
| E3 | 用户换登录方式登录 | 只要进入同一账号，数据与会员权益完整保留 |
| E4 | 用户在国外出差/旅游/VPN | 账号地区与数据区域保持不变，不自动切换 |
| E5 | 恢复购买失败（无历史订阅记录） | 提示无待恢复的购买记录，不产生错误权益 |
| E6 | 绑定登录方式时该方式已绑定其他账号 | 提示该登录方式已绑定其他账号，需先解绑或改用其他方式 |
| E7 | 邮箱验证码登录（海外） | 发送邮箱验证码，验证通过后进入账号；不建立密码 |
| E8 | 用户解绑某登录方式后再次用该方式登录 | 该方式已解绑，不再进入原账号；如用户希望重新关联，需再次到「账号与安全」主动绑定 |
| E9 | 用户注销账号 | 二次确认后注销；注销后账号数据按注销规则处理，会员权益终止 |
| E10 | 连续多次密码错误 | 临时锁定登录，防止暴力破解；提示稍后再试或改用验证码登录 |
